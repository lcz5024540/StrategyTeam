## 但仍然 0 PENDING — 新发现

部署后 9 分钟内 16 个新任务全 PAPER_SHADOW，**0 个触发 `MARKET_END_AT_STALE_BUT_ACTIVE` 分支**。

### 根因：我的短路条件太严

代码：
```java
if (remainingMs <= 0) {
    if (!marketState.isActive() || !marketState.acceptingOrders()) {
        firstRejectGate = "G6_MARKET_EXPIRED";   // 仍然拒绝
    } else {
        reasons.add("[MARKET_END_AT_STALE_BUT_ACTIVE] ...");  // 放行
    }
}
```

但 `marketState` 来自 `marketStateService.refreshMarket(...)`，**它实时调 Polymarket Gamma API** 然后用响应里的 `acceptingOrders` 字段（`SmartWalletMarketStateService.java:319`）：

```java
boolean acceptingOrders = metadata == null || metadata.isAcceptingOrders();
```

**Polymarket 自己的 API 在 market 过了 endAt 后会立即把 `acceptingOrders` 设成 false**——尽管我们 DB 里 `accepting_orders=1` 是过去的快照。

实测：两个被拒的 marketId DB 显示 lifecycle=ACTIVE+accepting_orders=1，但风控运行时拿到的 snapshot 里 `acceptingOrders=false`，导致进 IF 分支拒绝。

## 真相

**Polymarket 系统的语义就是：endAt 过 = 不再 accepting**。我们想要"放行 endAt 过期但市场仍可下单"的市场，但**这类市场实际上不存在**——只要 endAt 过，Polymarket 就关掉接单。

我的 Q3 修复**逻辑上没错，但对应的"放行场景"在 Polymarket 上几乎不存在**。

## 进一步选项

### 选项 A · 把 `acceptingOrders` 检查也去掉（激进）

```java
if (remainingMs <= 0) {
    // 只要 marketLifecycle 仍 ACTIVE（来自 DB），就放行
    if (!marketState.isActive()) {
        // 上游 isActive 检查已经处理了, 这里冗余, 不重复设 gate
    } else {
        reasons.add("[MARKET_END_AT_STALE_BUT_ACTIVE] ...");
    }
}
```

**风险**：实际下单到 Polymarket 会被 reject（因为 Polymarket 自己不接单）。订单进了 `smart_wallet_order` 但 status 是 FAILED。看起来 pipeline 通了但实际是空响。

### 选项 B · 接受现状：G6 拒绝是正确的（endAt 过期的市场确实跟不了）

那真正的问题就回到 Q1/Q2：
- 不是 G6 误判
- 是 **trade_event 入库太晚**，到我们这边时 leader 的目标市场 Polymarket 已经关单了
- 解决：缩短 sync 周期 + IntentAggregation 窗口（Q1 yml 已经改了 window 5→2）

### 选项 C · 在 leader 下单时间 vs market endAt 之间做检查

**关键洞察**：如果 leader 在 `T0` 下单，那时市场仍在接单。我们应该看 **`event.openedAt`** 时的市场状态，而不是"现在"的状态。

```java
if (remainingMs <= 0) {
    // 改为：endAt 是否在 event.openedAt 之前？
    long eventOpenedAt = event.getOpenedAt() != null ? event.getOpenedAt().getTime() : System.currentTimeMillis();
    if (endAt <= eventOpenedAt) {
        // leader 下单时市场就已经过期 → 信号本身就有问题, 拒
        firstRejectGate = "G6_MARKET_EXPIRED";
    } else {
        // leader 下单时市场还开着, 但我们处理时已过 → 这是 sync 延迟造成的, 信号本身是好的
        // 但实际还能否跟单要看现在 acceptingOrders
        if (marketState.acceptingOrders()) {
            reasons.add("[MARKET_ENDED_AFTER_LEADER_TRADE_BUT_STILL_ACCEPTING]");
        } else {
            firstRejectGate = "G6_MARKET_CLOSED_AFTER_LEADER_TRADE";
            reasons.add("Leader traded valid market but it has since closed.");
        }
    }
}
```
