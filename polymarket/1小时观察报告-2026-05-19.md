## ⚠️ 还没出现 PENDING/FOLLOWED 的 3 个原因

### 原因 1：stake multiplier 叠加过狠（最致命）

合理的 Kelly stake $24.91 被 4 层乘数压到 $0.50：
- `BEHAVIOR_STAKE 0.85`（FAST_STOP_LOSS 行为）
- `LONG_HORIZON_STAKE 0.50` × 2 次（市场类型 + Kelly 阶段都乘）  
- `MANUAL_ALLOWLIST_STAKE_MULTIPLIER 0.50`
- `SPIKE_STAKE`（slippage spike 0.474 时再砍）

**累积乘数 ≈ 0.85 × 0.5 × 0.5 × 0.5 ≈ 0.106** — 把 $24.91 砍到 $2.65，再被 EXPOSURE_CLIP 砍到 0.50。

## 🎯 还差什么才能开单（按 ROI 推荐）

### 方案 A · 强行打开 stake 下限（最简单，立即见效）

调高 `execution-wallet.min-order-usdc` 不是办法（会让真实 LIVE 单太小）。
反而应该**降低 stake 缩减系数**。yml 加：

```yaml
smart-wallet:
  signal-risk:
    # 砍掉 LONG_HORIZON 市场的双重 0.5 缩减
    long-horizon-stake-multiplier: 1.0      # 默认 0.5
    long-horizon-kelly-stake-multiplier: 1.0 # 默认 0.5
    # 砍掉 SPIKE 缩减
    enable-spike-stake-reduction: false
```

（参数名待验证，看 SignalRiskService 实际字段）

### 方案 B · 守护 TOP 7 钱包不被回退 COLD

```sql
-- 强制 manual_watch_enabled=1（refresh 仍可能覆盖 qualified，但保留 watch_enabled 不易动）
UPDATE smart_wallet_profile SET manual_watch_enabled=1
WHERE wallet_address IN ('0x56687bf447db6ffa42ffe2204a05edaa20f55839', ...);
```

但 `applyQualificationState` 里 `watchEnabled = qualified && manualWatchEnabled` 仍要求 qualified=true。**真正治本需要修 code**让 manual_watch_enabled=1 强制 HOT 而不依赖 qualified。

### 方案 C · 修 Spring env var binding（治本）

问题源头：`SMART_WALLET_MIN_WALLET_SCORE` 和 `MIN_TOTAL_TRADES` 环境变量虽在 JVM env 里，但 Spring 没 bind 进 properties。如果能修好这个，profile refresh 自然用 0.50/21 阈值，0x56687bf4 + 0x2005d16a + 几个其他 wallet_score>=0.50 的能进 HOT。

可能解决：用 `-D` 系统属性而不是环境变量。改 JAVA_OPTS 加 `-Dsmart-wallet.min-wallet-score=0.50 -Dsmart-wallet.min-total-trades=21`。但之前看到 env 文件里的 JAVA_OPTS append 不生效（脚本 cache）—— 需要更稳的做法。
