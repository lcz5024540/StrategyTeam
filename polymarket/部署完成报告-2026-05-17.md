## ⚠️ 仍存在的限制（无法靠代码救）

### Polymarket 上游本身就不返回 endAt

日志里能看到 `SmartWalletMarketStateService` 直接说：

```text
[ACTIVE_MARKET_METADATA_INCOMPLETE] 
  marketId=0x87de... 
  question="Will the 10-year Treasury yield dip below 3.8% before 2027?"
  refreshResult=REFRESHED_INCOMPLETE 
  missingFields=[marketEndAt]    ← Polymarket Gamma 自己就没给 endAt
```

这类长周期市场（"... before 2027"）Polymarket 自己也没设具体 endDate。我的 Fix 1A/1B/2 能让有 endAt 的市场及时流进 DB，但 Polymarket 本身没的市场救不了。

**进一步治本（如果你要做）**：在 `SmartWalletSignalRiskService` 的 G6 块里，当 `endAt == null` 但 `lifecycle=ACTIVE` 且 `accepting_orders=1` 时，认定市场可交易（而不是按 EXPIRED 拒）。这是 1-3 行的额外修改，但属于策略行为变更，建议你 review 后再决定。

### MarketInfoEndAtRefreshJob 日志暂时没看到

服务 22:56 启动，initialDelay=60s + fixedDelay=10min 应该已经跑 1 轮。但 `job-current.log` 没看到 `[MarketInfoEndAtRefreshJob]` 的日志输出。两种可能：
- A) 第一轮跑了但 `stale.isEmpty()` 返回 true（只 DEBUG 日志，不可见）
- B) `@ConfigurationProperties` 没 bind `marketInfoRefresh` 子配置 → 默认 `cfg == null` → 直接返回

由于我设的默认 `enabled=true` 写在 Java 字段里，理论上即使 yml 没配也应该 work。需要服务再跑 10-30 分钟观察。

但是**`backfillTaskMarketEndAt` 已经活了**——你可以手动触发 web 端的 `BACKFILL_MARKET_END_AT` HTTP endpoint 立即测试（路由通过 `SmartWalletAccountingController`）。
