## 真正的根因（修正 V1 报告）

V1 报告里说"56% 是 G6 市场过期"，**这个数字本身没错，但只是表象**。深挖之后实际上是**两条独立瓶颈叠加**：

### 瓶颈 A · `wallet_score` 阈值卡死全表（最致命）

74 个 profile 五条件过关情况：

| 条件 | 阈值 | 通过数 | 通过率 |
|------|------|-------|-------|
| `win_rate >= 0.62` | 0.62 | 46 | 62% |
| **`wallet_score >= 0.70`** | **0.70** | **3** | **4%** ← 瓶颈 |
| `total_trades >= 25` | 25 | 24 | 32% |
| `realized_pnl_usdc >= 1000` | $1000 | 60 | 81% |
| `max_drawdown_rate <= 0.25` | 0.25 | 34 | 46% |
| **5 条全过 (qualified)** | — | **1** | **1.4%** |
| **watch_enabled = 1** | — | **0** | **0%** |

唯一 1 个 qualified 的钱包还被下游 observe_cooldown / behavior / executable 检查挡掉，最终 0 个进入 watch_enabled。**整个 watchlist 主线事实上瘫了**。

### 瓶颈 B · 市场元数据 77% 缺 endAt

70,176 行 market_info：

| 状态 | 数量 | 占比 |
|------|-----|------|
| **`market_end_at IS NULL`** | **53,614** | **76.4%** |
| `market_end_at` 已过期 | 14,464 | 20.6% |
| `market_end_at` 在未来 | **2,098** | **3.0%** ← 仅有 |
| `market_lifecycle='ACTIVE'` 标记 | 15,706 | 22.4% |
| `accepting_orders=1` 标记 | 15,834 | 22.6% |

数据自相矛盾：lifecycle 标 ACTIVE 的有 15,706 个，**但 endAt 真在未来的只有 2,098 个**。差出来的 ~13,600 个市场 lifecycle 说 ACTIVE 但 endAt 已过/NULL —— 这是元数据写入逻辑的 bug。

### 两条瓶颈对最近 6h 任务的实际影响

| 市场状态 | 任务数 | 拒绝原因 |
|----------|-------|---------|
| endAt 在未来 + lifecycle ACTIVE | **41** (45%) | **39 个 PROFILE_BEHAVIOR**, 1 个 NON_TRADABLE, 1 个 PRICE |
| endAt 已过 + RESOLVED | 25 (27%) | 显然 G6 |
| endAt 已过 + lifecycle ACTIVE | 18 (20%) | G6（数据矛盾） |
| endAt NULL + RESOLVED | 4 | G6 |
| endAt NULL + lifecycle ACTIVE | 3 | G6 |

**关键发现**：即使在正常活跃的市场上（41 个），39 个被 PROFILE_BEHAVIOR 拒——也就是 G2 行为画像门。所以**就算把市场 endAt 修干净，也救不回这些**。

## IntentAggregation 排除嫌疑 ✓

担心的"同市场金额合并逻辑坏了"——查完发现**它没坏**：

- 538 个 task 里 99.1% 都有 `intent_key` 设置
- fragment_count 分布：`2 → 530`, `3 → 3`, `4 → 2`, `5 → 1`, `6 → 1`, `7 → 1`，只有 5 条 NULL
- 实测验证 0x2005d16a... 钱包的 6 个事件（103231, 103238, 103241, 103245, 103246, 103249）合并成了 3 个 task（fragment_count 都是 2），符合 5 分钟窗口逻辑

聚合后的 stake 实际很合理（$7.63, $2560, $10.13），但 3 个 task 仍然 PAPER_SHADOW。所以**问题不在聚合，在风控判定**。
