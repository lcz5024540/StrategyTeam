# Polymarket 跟单策略 — 开单流程检查点 & 白名单处理分析

> 分析日期：2026-05-17
> 主要代码入口：
> - `SmartWalletFollowTaskService.recordTradeEvent / createFollowTaskIfQualified`
> - `SmartWalletSignalRiskService.evaluate`
> - `SmartWalletManualAllowlistService`
> - `AllowlistSignalAggregationService`
> - `LoggingPolymarketExecutionGateway.execute` / `PolymarketClobExecutionService.executeFollowTask`

---

## 一、开单主流程（S1 → S7）

下游交易事件从 WebSocket 监听器进入后，要走完 7 个串行阶段，每个阶段都对应若干 Gate 检查。任何阶段拒绝都不会真的下单 —— 但会落库为 `SKIPPED` / `PAPER_SHADOW` 任务，供回溯。

```text
        ┌─────────────────────────────────────────────────────────────┐
S1 ──►  │ recordTradeEvent                                            │
        │  • externalTradeId 去重（已存在则跳过）                      │
        │  • 入库 smart_wallet_trade_event，派生 traceId                │
        └─────────────────────────────────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S2 ──►  │ createFollowTaskIfQualified  —— 钱包准入                   │
        │  ▸ sourceEventId 去重                                        │
        │  ▸ Intent 聚合 (FollowIntentAggregationService)              │
        │  ▸ G1_MANUAL_BLOCKLIST  →  阻断                              │
        │  ▸ profile + manualAllowlist 双轨准入                         │
        │      · 任一存在即放行；都不存在 → 拒绝（G1_WATCHLIST）         │
        └─────────────────────────┬───────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S3 ──►  │ 智能增强候选 (enrichAndSaveCandidate)                       │
        │  ▸ 钱包 → 实体ID 解析 + 共识去重                              │
        │  ▸ enrichmentStatus = PENDING 时落 SKIPPED                   │
        └─────────────────────────┬───────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S4 ──►  │ Market 状态检查 (refreshMarketState)                        │
        │  ▸ G6 系列：MARKET_NOT_ACTIVE / EXPIRED /                    │
        │      END_TOO_FAR / END_AT_MISSING_FORCE_REFRESH              │
        └─────────────────────────┬───────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S5 ──►  │ 风控评估 SmartWalletSignalRiskService.evaluate              │
        │     G1 → G13 共 13 个阶段（见下表）                          │
        │     缓存 TTL = 60s, key = taskId|updatedAt|policyTag         │
        └─────────────────────────┬───────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S6 ──►  │ 跟单任务落库                                                │
        │  • status = PENDING / SKIPPED / PAPER_SHADOW                  │
        │  • executionMode = LIVE / PAPER / PAPER_SHADOW / BLOCKLIST    │
        │  • 拒绝/降级时 SignalShadowRecorder 写影子记账                 │
        └─────────────────────────┬───────────────────────────────────┘
                                  │
        ┌─────────────────────────▼───────────────────────────────────┐
S7 ──►  │ 执行 executeTaskNow → PolymarketExecutionGateway            │
        │  ▸ LIVE 前再次 evaluateTask（防止状态变化）                   │
        │  ▸ enforceManualAllowlistLiveLimits（白名单 LIVE 限额）       │
        │  ▸ PolymarketOrderRequestFactory.prepare                     │
        │  ▸ clobClientRouter.placeOrder → 真实 CLOB                   │
        │  ▸ Maker-only / GTC 超时撤单 tracker 注册                     │
        └─────────────────────────────────────────────────────────────┘
```

## 二、Gate 检查清单（S5 风控评估的 13 道闸门）

`SmartWalletSignalRiskService.evaluate()` 内部用 `firstRejectGate` 串联，第一个拒绝即记录但仍继续跑完全部 reasons，便于做 blocker 统计。

| Gate | 编号 | 检查项 | 触发拒绝码 |
|------|------|--------|--------------|
| G1 钱包准入 | G1 | manual blocklist / manualWatchEnabled=false / 观察冷却 / 白名单缺 profile / watchlist 资质 | `G1_MANUAL_BLOCKLIST`, `G1_MANUAL_WATCH_DISABLED`, `G1_OBSERVE_COOLDOWN`, `G1_ALLOWLIST_PROFILE_MISSING`, `G1_WATCHLIST_UNQUALIFIED` |
| G2 Archetype/Behavior | G2, G2c | archetype=OBSERVE_ONLY、行为档案=FAST_EXIT_OR_SKIP、Leader 滚动表现(SUSPENDED/COOLING)、Leader 行为漂移(DRIFTED_SEVERE/DRIFTED) | `G2_ARCHETYPE_OBSERVE_ONLY`, `G2_BEHAVIOR_FAST_EXIT`, `G2_LEADER_ROLLING_SUSPENDED`, `G2c_LEADER_DRIFT_SEVERE` |
| G3 触发金额 / 价格带 | G3 | trigger notional < min；价格不在 [minFollowPrice, maxFollowPrice] | `G3_TRIGGER_SIZE_TOO_SMALL`, `G3_PRICE_OUT_OF_RANGE` |
| G4 组合约束 | G4 | 同时开仓数、总开仓成本、可用资金 | `G4_MAX_OPEN_POSITIONS`, `G4_MAX_TOTAL_OPEN_COST`, `G4_CAPITAL_DEPLETED` |
| G5 信号新鲜度 | G5 | event.openedAt → now 超过 lane 允许年龄 | `G5_SIGNAL_STALE(age=…s,max=…s)` |
| G6 市场状态 | G6 | inactive / expired / endAt 数据质量异常 / 重新拉后仍非活跃 | `G6_MARKET_NOT_ACTIVE`, `G6_MARKET_EXPIRED`, `G6_MARKET_END_TOO_FAR`, `G6_MARKET_END_DATA_QUALITY`, `G6_MARKET_NOT_ACTIVE_AFTER_FORCE_REFRESH` |
| G7 业务规则 | G7 | SELL 禁用、快事件入场禁用、反向已持仓、重复 pending 任务、相同 market+outcome 订单上限、Leader 持仓非盈利、入场时机 | `G7_SELL_DISABLED`, `G7_FAST_EVENT_BLOCKED`, `G7_OPPOSITE_POSITION_EXISTS`, `G7_DUPLICATE_PENDING_TASK`, `G7_OPPOSITE_PENDING_TASK`, `G7_MARKET_OUTCOME_ORDER_LIMIT`, `G7_LEADER_POSITION_NOT_PROFITABLE`, `G7_ENTRY_TIMING` |
| G8c 流动性深度 | G8c | 簿口深度不足 / 缩量后仍低于最小下单额 | `G8c_DEPTH_INSUFFICIENT`, `G8c_DEPTH_DOWNSIZE_BELOW_MIN` |
| G9 集中度 | G9 | 数据缺失 / 极端集中 / 高集中 / 鲸鱼信号阻断 | `G9_CONCENTRATION_DATA_UNAVAILABLE`, `G9_EXTREME_CONCENTRATION_BLOCK`, `G9_HIGH_CONCENTRATION_BLOCK`, `G9_WHALE_SIGNAL_BLOCK` |
| G10 Kelly / 仓位规模 | G10 / G10a / G10b / G10c | Kelly EV 为负、白名单聚合缓冲、最低下单额、暴露上限（单市场/地址/总 TVL）、暴露 clip 后过低 | `G10_KELLY_NEGATIVE_EV`, `G10a_ALLOWLIST_SIGNAL_BUFFERED`, `G10b_FINAL_STAKE_BELOW_MIN`, `G10c_EXPOSURE_LIMIT(…)`, `G10c_EXPOSURE_CLIP_BELOW_MIN` |
| G11 盈利性 / 微结构 | G11 | profitability、概率阈值、price-impact bps、滑点成本、剩余到期时间、滑点尖峰概率、价差 P70、信号评分模型 | `G11_PROFITABILITY_TOO_LOW`, `G11_PROBABILITY_BELOW_THRESHOLD`, `G11_PRICE_IMPACT_REJECT`, `G11_SLIPPAGE_COST_TOO_HIGH`, `G11_TIME_TO_EXPIRY_REJECT`, `G11_SLIPPAGE_SPIKE_PROB_TOO_HIGH`, `G11_SPREAD_P70_REJECT`, `G11_SIGNAL_SCORE_TOO_LOW` |
| G12 入场策略路由 | G12 | 入场策略路由（MAKER_ONLY / IOC / hybrid）拒绝 | `G12_ENTRY_STRATEGY_REJECTED` |
| G13 加仓规则 | G13 | 重复仓加仓预算、最小加仓单、加仓条件不满足、不允许加仓 | `G13_SCALE_UP_BUDGET`, `G13_SCALE_UP_MIN_ORDER`, `G13_SCALE_UP_CONDITIONS_FAILED`, `G13_DUPLICATE_POSITION_NO_SCALEUP_QUALIFY`, `G13_DUPLICATE_POSITION_SCALEUP_DISABLED` |

## 三、流程之外的"二次防线"

风控通过后并不直接下单，还有两道边界：

1. **`SmartWalletFollowTaskService.executeTaskNow(LIVE)`**
   - 仅 PENDING 任务可推到 LIVE
   - 再次调用 `evaluateTask`，如果状态变化（市场失效、白名单失效…）会被阻断
   - `enforceManualAllowlistLiveLimits()`：再次验证白名单仍激活 + allowsLive + profile 存在 + 未触日上限

2. **`LoggingPolymarketExecutionGateway.execute(LIVE)`**
   - `walletContextLoader.requireLiveContext()`：强制拿到 LIVE 钱包上下文
   - `PolymarketOrderRequestFactory.prepare(signal, wallet)`：再次对齐 tickSize、negRisk、size、price
   - 真正调 `clobClientRouter.placeOrder` 进 CLOB
   - 成功后注册：`MakerOnlyOrderTimeoutTracker.register(...)` + `GtcOrderTimeoutTracker.register(...)`，60s 未成交自动撤单

只有 `properties.isAutoExecutionEnabled() == true` **且** `isAllowlistLiveEnabled() == true`（或非白名单地址走常规通道）才能解锁 LIVE，否则 `resolveTaskExecutionMode` 强制降级为 PAPER。

## 四、白名单地址的差异化处理

白名单（manual allowlist）= 运营手工加入的 LEADER 地址，绕过观察资质要求，但仍要走交易级风控。核心库表 `smart_wallet_manual_allowlist`，由 `SmartWalletManualAllowlistService` 管理。

### 4.1 入站准入 —— 哪些 Gate 直接被绕过

| 检查 | 白名单行为 |
|------|-----------|
| G1 watchlist 资质 (`isExecutableProfile`) | **绕过**（"Address-profile admission checks are bypassed only"） |
| G1 观察冷却 | **绕过**（COOLDOWN_BYPASS），但日志会保留原因 |
| G1 manual blocklist | **不能绕过**（黑名单优先级最高） |
| G1 manualWatchDisabled | **不能绕过**（手动设置为 observe-only 优先） |
| G2 archetype = OBSERVE_ONLY | **绕过** |
| G2 behavior = FAST_EXIT_OR_SKIP | **绕过** |
| G2 Leader 滚动 SUSPENDED/COOLING | 仅在 `risk.manualAllowlistBypassLeaderRollingGate=true` 时绕过 |
| G2c Leader 行为漂移 | 仅在 `risk.manualAllowlistBypassLeaderDriftGate=true` 时绕过 |
| G7 快事件入场禁用 | 仅在 `risk.manualAllowlistBypassFastEventBlock=true` 时绕过 |
| G10 Kelly 负 EV | 仅在 `risk.manualAllowlistBypassKellyNegativeEv=true` 时绕过 |
| G11 信号评分太低 | 仅当 `manualAllowlistApplied && !consensusScoreFailed` 时跳过该闸门 |

> 备注：在 `G1_ALLOWLIST_PROFILE_MISSING` 这条特殊路径——profile 还没建好但已在白名单上——会被允许做 PAPER 影子观察，但 **禁止 LIVE 执行**，必须等指标补齐。

### 4.2 入站参数放宽

| 阈值 | 普通地址 | 白名单地址 |
|------|---------|-----------|
| 价格带 (`min/maxFollowPrice`) | `risk.minFollowPrice` / `risk.maxFollowPrice` | 强制扩到 **[0.02, 0.98]**，且超出常规带时仅按"距离比"线性 clamp stake（最低 30%） |
| 最小触发金额 (`minTriggerSizeUsdc`) | `risk.minTriggerSizeUsdc` | 兜底降到 **$1**（`MANUAL_ALLOWLIST_TRIGGER_SIZE_BYPASS`） |
| `maxStakeToTriggerNotionalRatio` | 配置值（通常 <1） | 强制改为 **1.0**（可下到 trigger 同等金额） |
| 信号年龄 | lane 默认值 | paper-canary lane 允许更长 |

### 4.3 仓位规模换算

`SmartWalletManualAllowlistService` 给每条白名单记录维护：

- **stakeMultiplier**（默认 0.50，上限 1.00）—— `recommendedStake = base × multiplier`
- **maxLiveOrdersPerDay**（默认 5）—— 当日 LIVE 订单数封顶
- **maxLiveOrdersPerRun**（默认 2）—— 同一次扫描批量推 LIVE 的上限
- **allowedExecutionModes**（PAPER / LIVE / BOTH，默认 PAPER）
- **expiresAt**（默认 30 天，过期自动 DISABLED via `cleanupExpired`）

### 4.4 小额信号的聚合缓冲（G10a）

白名单地址常常资金体量比策略大几十倍，等比缩放后单笔可能 < $1，落不到 Polymarket 最低下单线。`AllowlistSignalAggregationService` 因此承担"小额累计 → 集中下单"的角色：

```text
scaled stake < minOrderUsdc?
        │  yes
        ▼
allowlist-aggregation enabled?  ──► no  ──► 走常规 G10b
        │  yes
        ▼
key = marketId|outcome|walletAddress
缓冲累积；同 key 累计 ≥ minOrderUsdc → action=EXECUTE_NOW
否则 action=BUFFERED → 当前信号 reject 码 G10a_ALLOWLIST_SIGNAL_BUFFERED
（buffer 有时间窗口，超时丢弃以避免过期市场环境）
```

### 4.5 执行阶段的"再确认"

进入 `executeTaskNow(LIVE)` 后，白名单专属的 `enforceManualAllowlistLiveLimits()` 必须全部通过：

1. 白名单仍 ACTIVE 且未过期
2. `allowsLive(entity) == true`（allowedExecutionModes 包含 LIVE/BOTH）
3. profile 存在（`getWalletProfileByAddress(addr) != null`）
4. 当日 LIVE 数未达 `maxLiveOrdersPerDay`

任何一条失败 → 抛 `IllegalStateException("[MANUAL_ALLOWLIST_LIVE_LIMIT_BLOCK] …")`，整笔 LIVE 撤回。

另外，`SmartWalletFollowTaskService.listManualAllowlistTasks()` 在为同一 wallet 累计推 LIVE 时还会按 `maxLiveOrdersPerRun` 截断，避免一次扫描把当日额度用爆。

### 4.6 执行模式选型 `resolveTaskExecutionMode`

```text
SINGLE_WALLET_PAPER_CANARY?  ─► PAPER
auto-execution-enabled=false ─► PAPER
allowlist-live-enabled=false ─► PAPER
manualAllowlist active + allowsLive + profile≠null ─► LIVE
否则 ─► PAPER
```

## 五、关键检查点速查

```
S1 去重         externalTradeId 去重
S2 准入         blocklist > watchDisabled > profile/allowlist 二选一
S3 增强         实体解析失败 → 暂存为 PENDING (SKIPPED)
S4 市场         active/endAt/数据质量
S5 风控         G1~G13 全量评估，60s 缓存
S6 落库         任务 status + executionMode + shadow 记账
S7 执行         二次 evaluate + enforceManualAllowlistLiveLimits
                + prepare + placeOrder + timeout tracker
```

白名单的"双重身份"——既能突破观察资质门，又要交出 stake 缩放 + 日限额 + Live 二次校验——使得它和"普通 watch profile"在系统里形成了两条独立但合流的开单链路。
