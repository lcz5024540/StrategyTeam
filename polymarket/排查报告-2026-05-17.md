## 三、原因拆解

### 3.1 主要矛盾：G6 市场已过期占 56%

事件本身的 `opened_at` 距 `marketEndAt` 已经很近甚至超过：
- 样本 #101645 的 reasons 链里直接说 "Market is already at or past expected end time"
- `G6_MARKET_EXPIRED_AFTER_FORCE_REFRESH` 占 31% 表示：从缓存看市场状态不明，强制刷新后发现确实已结束

**可能性**：
1. **被关注的 leader 在做"快事件" / 短时窗市场**（剩余分钟数极少的事件），信号一进系统就过期
2. **市场元数据 `marketEndAt` 缓存陈旧**，导致初次判断未拦截、强刷后才拦
3. **5/14 部署后某段逻辑变更**让"剩余时间"判定更严格——成功率从 0.5% → 0% 的本质原因之一

### 3.2 次要矛盾：触发金额太小 + Kelly 负 EV
- Leader 单笔 trade notional 经常 $0.5~$2，被 `maxStakeToTriggerNotionalRatio` 限制后我方 stake 不到 $0.1
- 即使白名单把 `minTriggerSizeUsdc` 兜底到 $1，过 trigger 闸门也只是延后，到 G10 Kelly 算下来 EV 负又被拒
- Kelly 用的 `expectedReturnFactor=0.0000` → 价格/胜率组合下没正期望

### 3.3 上游数据质量
- 5 个白名单 leader 全部 `NOISE_OR_INSUFFICIENT`、`FAST_STOP_LOSS`、`settlementCompletionRate=0.005` ← 这些 leader 几乎没有结算样本，模型把 `leaderReliabilityFactor` 压到 0.15，`riskPenalty` 拉到 0.71，于是 SIGNAL_SCORE=0
- `watch_enabled=0` 全部为 0，意味着观察名单这条主线根本没在跑——**整个系统现在 100% 依赖手工白名单做"小流量金"**

## 四、修复建议（按 ROI 从高到低）

### Action 1 · 验证 5/14 部署到底改了什么（最高优先级）
- 这是从 0.5% 直接掉到 0% 的转折点
- 跟 git/CI 对一下 commit 范围，重点看 `SmartWalletSignalRiskService.evaluate` 里 G6（`marketState`/`marketEndAt` 相关代码）和 G10（Kelly / exposure-clip）有没有改阈值或判定条件
- 实测：找一条 5/13 日 FOLLOWED 任务的源事件，把它"重放"到当前服务，对比 reasons 链差异

### Action 2 · 把 `marketEndAt` 的时间窗口判定放宽
- 看 `SmartWalletSignalRiskService` 内 G6 块（约 line 415-460）
- 检查 `marketState.isActive()` 与 force-refresh 之后再判 `expired` 的逻辑：是否对"刚到期 N 秒"的市场也直接拒
- 测试环境可考虑暂时放宽 `marketEndMinRemainingMinutes` 或类似阈值，看 FOLLOWED 是否回升

### Action 3 · 启用白名单聚合（`allowlist-aggregation.enabled`）
- 当前 `application-test.yml` 没有覆盖这个 flag。代码默认应该是 false
- 启用后小额信号会按 `marketId|outcome|wallet` 累积，攒到 minOrder($1) 才下单 → 直接解决 `G3_TRIGGER_SIZE_TOO_SMALL` 和 `G10c_EXPOSURE_CLIP_BELOW_MIN`
- 临时验证方式（覆盖到 test）：
  ```yaml
  smart-wallet:
    allowlist-aggregation:
      enabled: true
      window-seconds: 600
  ```

### Action 4 · 处理"NOISE_OR_INSUFFICIENT" leader 问题
- 5 个白名单 leader 数据画像太差，被风控里多个 stake 缩放因子叠加打到 0
- 短期：把 `risk.manualAllowlistBypassKellyNegativeEv` 设 `true`，让白名单忽略负 EV（小流量金允许试错）
- 长期：用 `wallet_archetype` 工具重跑这 5 个地址，喂更多历史样本；或换更高质量的白名单 leader

### Action 5 · 恢复 watchlist 主线
- 74 个 profile, 0 watched → 主流程瘫了
- 检查 `profileStoreService.listWatchEnabled()` 为什么返回空：
  - 表里 `watch_enabled` 列是不是全 0？
  - 还是定时任务（`SmartWalletProfileTierDiagnosticReadService` / `LeaderRollingMonitorJob`）压根没把任何一个 promote 到 watch=1？

### Action 6 · 拉日志告警
- 当前 `job-error-current.log` 只有 11KB，但 `firstRejectGate` 满屏。建议：
  - 加一条监控：连续 N 小时无 PENDING/FOLLOWED 任务 → 告警
  - 在 PAPER 环境也能跑通的 canary case，定期注入测试事件
