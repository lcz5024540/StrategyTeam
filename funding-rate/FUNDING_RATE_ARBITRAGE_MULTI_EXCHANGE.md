# 多交易所资金费率套利策略

## 1. 策略定位

多交易所套利是指在不同交易所之间建立相反方向的合约仓位，利用资金费率差、价格差和流动性差异获取收益。典型形式是“低费率交易所做多，高费率交易所做空”，目标是赚取两个交易所之间的 funding spread。

## 2. 策略原理

### 2.1 基本操作

* **低费率交易所**：开多头。
* **高费率交易所**：开空头。
* **目标**：让两个交易所之间的净方向敞口尽量接近 0，持续赚取资金费率差。

### 2.2 收益来源

* **资金费率差收益**：高费率侧收到的资金费减去低费率侧支付的资金费。
* **价格收敛收益**：若跨所价差在平仓时向有利方向回归，可能获得额外收益。

### 2.3 主要成本

* 双边开平仓手续费。
* 两侧滑点与买卖价差。
* 跨所调拨资金或补保证金的时间成本。
* 部分场景下的借币、融资或提现费用。

## 3. 详细执行逻辑

### 3.1 标的与交易所筛选

* 只选择多个交易所都具有高流动性的标的。
* 仅在接口稳定、账户体系清晰、撮合深度足够的交易所组合间运行。

### 3.2 开仓条件

* 资金费率差 > 手续费 + 滑点 + 预留风险缓冲。
* 两侧盘口深度足以支撑目标仓位。
* 两侧价格差、标记价格机制、结算节奏处于可接受范围。
* 两侧保证金充足，且在极端行情下有再平衡方案。

### 3.3 开仓动作

1. 同步获取多交易所 funding、mark price、盘口和账户信息。
2. 计算 funding spread、预估净收益和双边可成交容量。
3. 同步下发两腿订单，尽量减少单腿裸露时间。
4. 若一腿成交一腿失败，立即在成交侧回补或平仓。

### 3.4 持仓监控

* 监控 funding spread 是否仍大于持有成本。
* 监控两侧保证金率是否失衡。
* 监控是否出现 API 延迟、提现异常、风控限制或仓位模式变化。

### 3.5 平仓条件

* funding spread 收窄到不足以覆盖摩擦成本。
* 某一侧资金费率方向反转且预计持续。
* 某一交易所保证金率恶化，需要优先降低暴露。
* 某一交易所出现接口异常、交易限制或信用风险事件。

## 4. 核心风险与注意事项

### 4.1 单腿成交风险

* 比单交易所更严重，因为两边分属不同交易所、不同撮合系统和不同网络链路。

### 4.2 交易所信用与运营风险

* 某一侧可能出现宕机、限仓、异常插针、无法撤单或无法提现。

### 4.3 保证金再平衡风险

* 极端行情下，一侧保证金率可能急剧恶化，而另一侧盈利无法即时跨所补入。

### 4.4 结算机制差异

* 不同交易所 funding 结算时间、标记价格计算方式和仓位模式可能不同。

### 4.5 价格与基差风险

* 跨所价格不一定稳定收敛。
* 即使 funding spread 看起来很高，也可能被异常价差和滑点吞噬。

## 5. 代码架构建议

### 5.1 模块划分

* **`exchange-adapter`**：统一不同交易所 funding、盘口、下单和账户接口。
* **`spread-monitor`**：实时计算 funding spread、价格 spread 和可成交容量。
* **`decision`**：判断是否开仓、减仓、平仓或暂停。
* **`execution`**：双腿同步下单、回滚和失败补偿。
* **`capital-manager`**：管理跨所资金分配与保证金补给。
* **`risk`**：统一评估交易所风险、接口风险和仓位风险。
