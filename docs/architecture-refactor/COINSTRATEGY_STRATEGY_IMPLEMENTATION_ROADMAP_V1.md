# CoinStrategy 策略体系实施路线图 v1

> **结论先行**：后续实现不再围绕单个指标修补，而按“策略总纲 → 子系统设计 → 数据与账本 → 回测验证 → 实盘灰度 → 页面驾驶舱”的顺序推进。第一阶段只做统一维度和因子快照，不直接扩大真实开仓；第二阶段重构趋势多模型；第三阶段恢复套利资金池；第四阶段做资金调度和统一页面。

---

文档维护原则：

```text

排期、里程碑、验收变化改 L3 路线图。
代码实现必须能回链到 L1/L2/L3 对应章节。
```

## 2. 总体实施顺序

策略体系分 7 个阶段推进。

| 阶段 | 名称 | 目标 | 是否影响实盘开仓 |
|---|---|---|---|
| P0 | 文档和方向冻结 | 建立总纲、趋势设计、路线图 | 否 |
| P1 | 统一维度与账本底座 | 补账户、策略族、模型、净盈亏口径 | 否 |
| P2 | 因子快照与候选观察 | 所有候选因子入库，页面可诊断 | 否 |
| P3 | 趋势多模型重构 | 拆模型、统一评分、统一 gate | 先观察，后灰度 |
| P4 | 回测系统闭环 | 覆盖 9/18–9/21 与更长历史样本 | 否 |
| P5 | 套利策略资金池 | 恢复稳定收益底仓，先单所现货合约对冲 | 灰度 |
| P6 | 资金调度与驾驶舱 | 趋势/套利/缓冲统一资金调度和页面 | 是，分阶段 |

## 4. P1：统一维度与账本底座

### 4.1 目标

先把“谁在赚钱、谁在亏钱、哪个账户、哪个策略、哪个模型”记录清楚。没有这个底座，趋势和套利都会变成看日志猜。

### 4.2 数据维度

| 维度 | 说明 | 使用位置 |
|---|---|---|
| `account_id` | 内部账户 ID | 多账号区分、手续费率、资金归属。 |
| `account_label` | 展示名 | 页面展示。 |
| `exchange` | 交易所 | HTX、后续 Binance/OKX。 |
| `strategy_family` | 策略族 | TREND / ARBITRAGE / GRID / RESERVE。 |
| `strategy_name` | 策略名 | HTX_TREND_V1、HTX_SPOT_PERP_FUNDING_V1。 |
| `model_name` | 模型名 | BOX_BREAKOUT、FIB_PULLBACK、MOMENTUM。 |
| `run_id` | 一次调度运行 ID | 串联候选、gate、订单和仓位。 |
| `factor_snapshot_id` | 因子快照 ID | 回放开仓依据。 |
| `net_pnl_after_fee` | 扣费后净盈亏 | 页面和回测第一口径。 |

### 4.3 任务清单

| 编号 | 任务 | 验收 |
|---|---|---|
| P1-T1 | 梳理现有 `htx_trend_position`、`htx_trend_order`、账户表和 dashboard 查询 | 列出字段缺口和兼容方案。 |
| P1-T2 | 新增或迁移账户表 | primary、TradeX 可从 DB 识别，不依赖配置展示。 |
| P1-T3 | 为订单/仓位补策略维度 | 页面可按 strategy_family / strategy_name / model_name 聚合。 |
| P1-T4 | 补净盈亏口径 | 所有统计默认 `realized_profit - entry_fee - close_fee`。 |
| P1-T5 | 页面总览改为策略族聚合 | 10 个/100 个账户时不堆卡片。 |

### 4.4 验收标准

```text
能按账户、策略族、策略名、模型名统计今日/昨日/历史净盈亏。
能区分趋势亏损、套利收益、网格收益。
能显示手续费占比，不再把未扣费 realized_profit 当主口径。
```

## 5. P2：因子快照与候选观察

### 5.1 目标

真实开仓前先把所有候选的因子记录下来。每一笔开仓或不开仓都能回答“为什么”。

### 5.2 数据表规划

| 表 | 用途 |
|---|---|
| `htx_trend_market_regime_snapshot` | 每轮市场分型：anchor、breadth、volatility、funding skew。 |
| `htx_trend_factor_snapshot` | 单币因子快照：多周期、结构、量价、成本、风险。 |
| `htx_trend_model_signal` | 各模型候选：模型名、方向、分数、gate 结果。 |
| `htx_trend_gate_audit` | gate 拦截明细：拒绝原因、阈值、实际值。 |

### 5.3 任务清单

| 编号 | 任务 | 验收 |
|---|---|---|
| P2-T1 | 实现市场分型快照 | 已完成：每轮扫描写入市场广度和 BTC/ETH 锚点快照。 |
| P2-T2 | 实现单币多周期因子 | 已完成：每个币在真实开仓判定之后记录 15m/30m/60m/4h/1d 的方向、EMA、ROC、ATR、ADX、Donchian 与数据可用性。 |
| P2-T3 | 实现结构因子 | 已完成第一刀：组合候选记录箱体、swing high/low、Fibonacci 来源、回踩区间、失效价和目标区。 |
| P2-T4 | 实现成本因子 | 账户手续费率、点差、深度、预期扣费后收益。 |
| P2-T5 | 页面展示候选观察 | 能看到候选、分数、gate 拒绝原因。 |

### 5.4 验收标准

```text
不改变真实下单逻辑。
至少连续观察 24 小时。
每轮 52 个币的候选、因子、gate 均可从 DB 查询。
页面可查看最近一次扫描和最近 100 个候选。
```

### 5.5 实施记录

| 日期 | 范围 | 结果 |
|---|---|---|
| 2026-09-22 | P2 证据快照第一刀 | 已补生产库目标区/Fibonacci 扩展字段迁移，消除候选写入的 schema drift。组合候选快照新增精确的此前突破 K、impulse 高低点、0.382/0.618 回踩区间、EMA 收复确认和结构窗口；每个扫描收盘价另写一条市场广度/BTC-ETH 锚点快照。Dashboard API 的候选记录现返回模型、policy、gate、失效价、目标区、R 倍数及关联因子快照。未改变开仓、平仓或仓位 sizing。 |
| 2026-09-22 | P2 单币多周期因子 | 扫描完成后，对全部白名单币种以受限并发写入独立 `trend-factor-multi-v1` 快照，覆盖 15m/30m/60m/4h/1d；每个周期记录方向、市场分型、分数、EMA、ATR/ATR%、ADX、ROC、成交量比、Donchian 和数据可用性。该步骤在候选 gate 与真实下单之后执行，保证可观测性不影响信号新鲜度；同时把新增 JSON 中的数值改为 JSON number，避免数值被错误序列化为字符串。 |

## 6. P3：趋势多模型重构

### 6.1 目标

把现有趋势逻辑拆成独立模型，候选统一排序，开仓统一 gate。

### 6.2 模型接口

```text
TrendSignalModel
  name()
  evaluate(MarketRegimeSnapshot, SymbolFactorSnapshot) -> ModelSignalCandidate
```

第一版模型：

| 模型 | 状态 | 说明 |
|---|---|---|
| `BOX_BREAKOUT` | 新增 | 横盘后放量突破。 |
| `FIB_PULLBACK_CONTINUATION` | 重写 | 必须有 swing/箱体来源和重新转强。 |
| `MULTI_TIMEFRAME_MOMENTUM` | 新增 | 捕捉小周期趋势，但必须多周期确认。 |
| `DONCHIAN_BREAKOUT` | 观察/可合并 | 先作为强突破参考，避免假突破过多。 |

### 6.3 任务清单

| 编号 | 任务 | 验收 |
|---|---|---|
| P3-T1 | 拆出 `TrendSignalModel` 接口 | 现有服务不再直接把单个信号送下单。 |
| P3-T2 | 实现统一候选对象 | 包含 entry price、invalidation price、expected net、score。 |
| P3-T3 | 重写 Fibonacci 模型 | `localMomentum-` 不允许直接开；必须 `fib_reclaim_signal=true`。 |
| P3-T4 | 实现箱体突破模型 | 能识别箱体边界、突破强度、假突破风险。 |
| P3-T5 | 实现多周期动量模型 | 至少 15m/30m/60m 两周期同向。 |
| P3-T6 | 实现统一候选排序 | 先按 gate，再按 score，再按流动性/风险。 |

### 6.4 验收标准

```text
相同 K 线输入下，每个模型输出独立候选。
DB 能查到每个模型为什么 PASS / REJECT / OBSERVE。
真实开仓入口只消费统一候选，不直接依赖某个模型内部逻辑。
```

## 7. P4：回测系统闭环

### 7.1 目标

先用历史 K 线验证，再动真实开仓。回测必须扣手续费、滑点和资金费影响。

### 7.2 数据样本

| 样本 | 用途 |
|---|---|
| 2026-09-18 | 好行情样本，验证能否捕捉上涨。 |
| 2026-09-19 | 差行情/回撤样本，验证能否少亏。 |
| 2026-09-20 | 中间状态样本，验证策略稳定性。 |
| 2026-09-21 | 真实亏损复盘样本，验证能否解释并修复。 |
| 后续 30/90 天 | 扩大样本，防止过拟合。 |

### 7.3 任务清单

| 编号 | 任务 | 验收 |
|---|---|---|
| P4-T1 | K 线下载和缓存 | 支持 15m/30m/60m/4h。 |
| P4-T2 | 回测事件引擎 | 模拟扫描、候选、gate、开仓、平仓。 |
| P4-T3 | 费用滑点模型 | 账户手续费率、点差、滑点、资金费可配置。 |
| P4-T4 | 报告输出 | 按模型、市场分型、币种、账户输出指标。 |
| P4-T5 | 对比实盘 | 能复现 9/21 亏损单的入场和平仓逻辑。 |

### 7.4 验收标准

```text
输出扣费后净收益、胜率、profit factor、最大回撤、MFE、MAE。
能说明每个模型在 BROAD_UP/BROAD_DOWN/MIXED/CHOP 下表现。
新模型未通过回测前不得扩大实盘仓位。
```

## 8. P5：套利策略资金池

### 8.1 目标

套利策略作为稳定收益底座，先恢复单交易所现货合约对冲资金费套利，再规划跨所套利。

### 8.2 子系统文档

| 模块 | 内容 |
|---|---|

| 跨所资金费套利 | 多交易所资金费差、基差、资金划转、对冲偏差。 |
| 资金费预测 | 当前资金费、下期预估、历史稳定性。 |
| 对冲完整性 | 现货与合约名义额匹配。 |
| 退出机制 | 资金费反转、基差风险、保证金风险。 |
| 收益账本 | 资金费、价差、手续费、滑点拆分。 |

## 10. 提交和上线边界

| 类型 | 规则 |
|---|---|
| 文档 | 可直接提交并推送。 |
| DB 表结构 | 先写迁移 SQL 和回滚说明，再部署。 |
| 因子快照 | 先观察，不影响交易。 |
