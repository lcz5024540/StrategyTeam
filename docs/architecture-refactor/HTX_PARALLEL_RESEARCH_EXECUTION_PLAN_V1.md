# HTX 趋势研究并行执行计划 v1

## 目的

在历史 K 线冻结完成前，提前完成不依赖真实历史样本的研究基础设施。它们只用于离线研究，不能改变实时候选、仓位、订单或交易开关。

## 统一链路

```text
独立模型候选与价格计划
        ↓
订单成交模拟（市价 / 限价 / IOC / 部分成交）
        ↓
成本模拟（滑点 / 双边费率 / 资金费）
        ↓
组合风险分配（仓位槽位 / 相关性簇 / 名义额）
        ↓
冻结数据驱动的结果标签与评估账本
        ↓
样本外报告与纸面准入判断
```

任何一层缺证据都只能输出 `INSUFFICIENT_EVIDENCE`；不能以模拟结果恢复真实开仓。

## 分批执行顺序

### Batch A：真实成交与组合约束

先完成 `PAR-01`、`PAR-02`、`PAR-03`。原因是任何模型在完整历史数据上运行前，都必须先明确“信号是否成交、成交多少、扣费与资金费后剩多少、是否被组合风险拒绝”。

验收：同一组合成候选在相同流动性、费率和风险限制下，输出完全确定的成交、拒绝和成本结果；不访问网络，不读账户凭据。

### Batch A 执行记录（2026-09-29）

`htx_trend_portfolio_simulator.py` 已实现并以合成输入验证。它不读取 K 线文件、账户或网络：市价可按可用流动性部分成交；被动限价/IOC 未触价不成交；正资金费下多头付费、空头收取；资金费缺失显式返回不可用；组合层按分数排序后记录重复币种、相关性簇、总名义额和仓位槽位的拒绝原因。

## Batch B：研究数据写入与订单类型对照

完成 `PAR-04`、`PAR-05`，使完整数据抵达后能够可恢复地写入账本，并比较订单类型，而非默认市价成交。

#### Batch B 执行记录（2026-09-29）

研究结果导入器已按 500 条逻辑批次保存同目录 checkpoint，checkpoint 固定关联结果文件 SHA-256 与数据集键。重启只处理未确认批次；已写入但未确认的最后一小批可安全重放，因为状态、标签、评估均由不可变键幂等保护。输入文件校验和变化则拒绝恢复，不能混合两份研究结论。



订单生命周期实验已完成：市价用下一根开盘价加不利滑点；被动限价可等待 `max_wait_bars`；IOC 仅在首根后续 K 线触价才成交；条件限价先完成触发、下一根才可触碰限价，避免同一根 OHLC 同时触发和成交的虚假假设。

## Batch C：模型扩展与报告

完成 `PAR-06`、`PAR-07`。所有模型保持同 K 线并行分析，组合层才负责去重和风险分配；报告只使用 `COMPLETE` 数据集的样本外结果。

## 与主计划的关系

本计划是 `HTX_QUANT_STRATEGY_REMEDIATION_PLAN_V1.md` 的并行实施轨道，分别服务 P3、P4、P5 与 P2。它不替代 P0 的数据完整性条件：没有完整冻结数据时，不产生模型盈利结论，不进入纸面或真实交易。
