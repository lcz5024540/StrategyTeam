# HTX 15 分钟趋势利润保护与动态减仓 v3

> 日期：2026-09-25  
> 范围：`FIB_PULLBACK_CONTINUATION` 的 `INTRADAY_15M` 仓位。  
> 状态：代码与回放已完成，**未部署，未开启真实减仓或真实 v3 平仓**。

## 1. 要修复的确定性问题

旧的首笔减仓条件是“达到 1R 或 Fibonacci 结构目标”。但 `1R` 由开仓价与初始止损的距离决定；初始止损是模型失效边界，可能刻意很宽，不能承担短周期的利润目标职责。

LTC 161 是直接例子：开仓 `72.92`、初始止损 `68.98`，风险距离 `3.94`，而 15 分钟 ATR 为 `1.342857`。旧 1R 目标是 `76.86`，距离开仓约 `+5.4%`、约 `2.93 ATR`。这对 15 分钟仓位是远端 runner 目标，而不是合理的首个利润保护门槛。

因此 v3 明确分离三件事：

| 内容 | 作用 | 是否用于首笔减仓 |
|---|---|---|
| 初始止损 / 模型失效价 | 控制最大错误与仓位 sizing | 否 |
| Fibonacci 扩展、1R、箱体量度目标 | 评估趋势剩余空间与 runner 价值 | 否，不能单独触发 |
| 成本、15 分钟 ATR、局部回吐与反转证据 | 决定何时保护和减小真实暴露 | 是 |

## 2. v3 决策规则

### 2.1 先武装利润保护

对多单，定义：

```text
全成本价差 = 实际开仓手续费 + 当前平仓预估手续费，除以当前剩余持仓标的数量
利润锁定距离 = 全成本价差 + 0.15 × ATR_15m
武装距离 = max(0.50 × ATR_15m, 利润锁定距离)
保护价 = 开仓价 + 利润锁定距离
```

空单方向相反。只有扣费后净浮盈至少达到 `2 × 预计平仓手续费`，并且持仓曾走过“武装距离”，才持久化 `trailing_armed_at` 和保护价。开仓费取 HTX 已成交的实际费用；仅历史缺失时才以当前账户费率回退估计。平仓费随当前价和账户费率实时估计。部分减仓后的 runner 只分摊仍持有张数对应的开仓费。该事实不会因后续回撤被撤销。

默认值都配置化，分别为：

| 参数 | 默认值 | 用途 |
|---|---:|---|
| `intradayProfitArmAtrMultiplier` | 0.50 | 首次武装所需 ATR 距离 |
| `intradayProfitLockAtrMultiplier` | 0.15 | 保护价超过成本的缓冲 |
| `intradayProfitPartialAtrMultiplier` | 0.75 | 有资格动态减仓的最小有利 excursion |
| `intradayProfitPullbackAtrMultiplier` | 0.40 | 从 MFE 回吐多少 ATR 后开始评估减仓 |
| `intradayProfitMinNetFeeMultiple` | 2.00 | 净浮盈相对于预计平仓费的最低门槛 |

### 2.2 动态减仓，而非到价机械卖出

满足以下全部条件才减仓：

1. 曾有至少 `0.75 ATR_15m` 的有利 excursion，且净收益覆盖成本门槛；
2. 从 MFE 回吐至少 `0.40 ATR_15m`；
3. 至少两类独立转弱证据成立：价格回吐、15 分钟 EMA/方向转弱、30m/60m/4h 反向、或市场广度反向；
4. 到下一个结构目标的扣费后预期收益，不再显著优于跌回保护价的风险。

减仓量不固定为 33%。它按“下一个结构目标的预期净收益 / 已保护风险”计算目标剩余张数；保留至少一张 runner。若无法形成有效 reduce-only 数量，则明确记录未执行原因。

### 2.3 runner 与全平

- 结构目标、1R 和 Fibonacci 扩展只用于衡量剩余收益，不能阻止已武装保护价被穿越后的退出。
- 已武装后穿越保护价：全平剩余 runner。
- 模型失效或初始止损：优先全平。
- 未武装且净亏的仓位：继续使用连续 `FLAT`、亏损预算和模型失效的有界回退，避免把亏损仓位无限期持有。

## 3. LTC 161 映射

| 项目 | 数值 |
|---|---:|
| 开仓价 | 72.92 |
| 初始止损 | 68.98 |
| 15 分钟 ATR | 1.342857 |
| 旧首笔 1R | 76.86 |
| v3 首次武装价 | 约 73.59 |
| v3 成本后保护价 | 约 73.18 |
| v3 具备动态减仓资格的 MFE | 约 73.93 |
| Fibonacci 结构目标 | 77.10 |

这里的 `73.59` 不是“到价就卖”，而是开始保护已经存在的利润；`73.93` 之后若发生至少 `0.40 ATR` 回吐且证据转弱，才计算应减多少。这样能避免把 15 分钟交易做成等待 5% 行情的长线单，也避免强趋势仅因一次小回踩就被机械卖掉。

## 4. 回放结果与边界

冻结事故样本继续使用同一组 HTX 15 分钟 K 线、生产信号、开仓价、张数和费率：

| 样本 | v3 结果 | 说明 |
|---|---|---|
| DOGE 153 | 04:30 `FULL_CLOSE`，模拟净 `+2.5995U` | 仍保留大部分原 v2 的盈利保护效果。 |
| SUI 154 | 00:00 `FULL_CLOSE`，模拟净 `+0.6212U` | 比 v2 的 00:15 / `+0.9672U` 更早锁定利润；牺牲部分延伸收益，换取不再依赖 1R。 |
| ZEC 159 | 窗口结束时 `ARM_TRAILING` | 冻结窗口缺少后续 K 线，不能伪造最终成交；证明其利润保护状态已可持久化。 |
| XRP 156 / 160 | 仍无终态 | 两笔只有两根完整 post-entry K 线，不能突破三根 `FLAT` 的回退确认假设。 |

这些是保守 K 线收盘价模拟，尚未纳入真实盘口和逐笔成交，不能作为真实收益承诺。

## 5. 上线顺序

1. 先部署 v3，但保持 `HTX_TREND_EXIT_ENGINE_V2_LIVE_ENABLED=false`，只写 `fib-exit-engine-v3` 决策账本；
2. 观察至少覆盖“武装、动态减仓候选、保护价穿越”三类真实场景，并复核保护价、证据、建议张数和实际 K 线；
3. 补真实成交时点盘口和逐笔成交数据，完成 XRP/ZEC 执行价归因；
4. 仅主账户小仓开启 v3 live；TradeX 继续关闭，旧 `HTX_TREND_PARTIAL_TAKE_PROFIT_LIVE_ENABLED` 保持关闭；
5. 对比 v2 与 v3 的扣费后净 PnL、PF、MFE 捕获率、盈利回吐率、过早退出率和最大回撤，再决定扩大范围。
