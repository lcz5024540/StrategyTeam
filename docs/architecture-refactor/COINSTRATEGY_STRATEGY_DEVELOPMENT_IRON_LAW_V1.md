# CoinStrategy 策略开发铁律 v1

> **结论先行**：以后 CoinStrategy 的任何策略新增、参数调整、指标引入、开仓/平仓规则改变、仓位规则改变，都必须先通过本铁律的研究闭环。没有冻结 K 线、没有同源回测、没有消融实验、没有成本压力、没有样本外或纸面交易验证的结果，不得进入实盘 Gate、排序、仓位 sizing 或退出动作。

## 1. 适用范围

本铁律适用于下列所有策略工作：

| 类型 | 例子 | 是否必须走本铁律 |
|---|---|---|
| 新策略 | 新增 Donchian、EMA/VWAP、套利、资金费策略。 | 是 |
| 新模型 / 新特征 | K 线斜率、收益率统计、波动率、成交量斜率、chop score、资金费率。 | 是 |
| 参数调整 | RSI、ATR、突破窗口、回踩窗口、止损、冷却、方向阈值。 | 是 |
| 开仓 / 平仓规则 | 试探性限价、分批止盈、利润保护、runner、time-stop。 | 是 |
| 仓位 / 风控规则 | 单笔风险、组合暴露、加仓、连续亏损降仓。 | 是 |
| 纯展示修复 | 页面文案、表格排序、不影响策略决策的展示。 | 可豁免，但必须标明不影响策略决策 |

## 2. 总体框架步骤

策略开发必须按下列顺序执行。前一阶段没有通过，后一阶段不能用其结论影响实盘。

| 阶段 | 名称 | 必须输出 | 禁止事项 |
|---|---|---|---|
| 1 | 策略卡片 | 策略名称、版本、周期、方向、品种、杠杆、市场假设、失效场景。 | 只有一句“看起来有效”就开始写代码。 |
| 2 | 数据冻结 | 原始 K 线、标准化 K 线、时间范围、时区、manifest、内容 hash、连续性报告。 | 使用未冻结、不可复现或缺口未标记的数据定标。 |
| 3 | 数据质量审计 | 时间升序、重复、缺失、OHLC 合理性、成交量异常、跳价、交易日历或全天候连续性。 | 把交易所返回数据默认视为干净数据。 |
| 4 | 指标与特征字典 | 每个指标的公式、窗口、滞后、用途、防前视边界、缺失处理。 | 先接入 Gate，再补公式说明。 |
| 5 | 信号状态机 | 突破、回踩、确认、卖出、冷却、重复信号、候选到订单状态。 | 把指标阈值直接等同于可下单信号。 |
| 6 | 仓位与风险 | 止损距离、单笔账户风险、仓位比例、单品种上限、组合上限、连续亏损规则。 | 混淆“止损距离”“仓位比例”和“账户最大损失”。 |
| 7 | 成本与执行假设 | 手续费、滑点、价差、资金费率、市场冲击、限价/市价/IOC/重报价场景。 | 用无成本回测指导真实交易。 |
| 8 | 同源回测 | 读取冻结数据、信号、成本、仓位、成交假设，输出交易账本和资金曲线。 | 用临时脚本近似替代生产合同。 |
| 9 | 消融与敏感性 | 单变量参数实验、移除单个指标/gate、full gate 对照、核心结构对照。 | 同时改多个模块后只报告收益变好。 |
| 10 | 样本外与稳健性 | 训练/验证/测试切分、walk-forward、成本压力、不同市场状态、样本量检查。 | 因测试集不好又回头调参。 |
| 11 | 纸面 / 模拟交易 | 外部模拟执行、成交回传、生命周期事件、错失率、滑点、费用和退出复盘。 | 直接用真实账户试错执行方式。 |
| 12 | 研究报告与准入 | 结论、失败案例、局限性、继续/修改/暂停、上线前检查清单。 | 只给一个收益率或胜率就申请上线。 |

## 3. K 线冻结铁律

K 线冻结是所有研究的第一依赖。没有合格冻结数据，就没有正式回测结论。

### 3.1 必须冻结的内容

每个冻结批次必须保存：

- 交易所原始响应；
- 标准化 OHLCV：`timestamp/open/high/low/close/volume`；
- symbol、timeframe、交易所、市场类型、合约面值；
- K 线开始时间、结束时间、统一时区；
- 采集时间、采集参数、分页边界；
- 内容 hash、manifest、数据版本；
- 采集失败、缺口、重复、倒序、异常价格记录。

### 3.2 连续性检查

全天候市场按固定 interval 检查。非全天候市场必须按交易日历检查，不能把休市误判为缺口。

| 检查项 | 标准 |
|---|---|
| 时间顺序 | timestamp 必须严格升序。 |
| 重复 K 线 | 同一 symbol x timeframe x timestamp 不得重复。 |
| 缺失 K 线 | 缺口必须列出起止时间和数量。 |
| OHLC 合理性 | high 不低于 open/close，low 不高于 open/close。 |
| 成交量 | 不得为负；极端异常必须标记。 |
| 跳价 | 大幅跳价必须保留并标记，不得静默删除。 |
| 数据完整性 | 任何缺口批次标记 `INCOMPLETE`，不得用于正式 PF、胜率或参数定标。 |

## 4. 未来函数与数据泄露铁律

所有指标和信号必须写清楚“当前时刻已经知道什么”。

| 场景 | 铁律 |
|---|---|
| 阻力位 / 支撑位 | 使用过去已完成 K 线，例如 rolling high 必须 shift。 |
| 收盘信号 | 当前 K 线收盘后生成信号，成交默认放到下一根 K 线或明确声明收盘成交假设。 |
| 回踩确认 | 不得用未来几根 K 线确认当前是否可以买入。 |
| 样本统计 | 均值、标准差、回归、协整、相关性等只能用当时以前的数据。 |
| 标准化 / 清洗 | 训练集、验证集、测试集必须独立处理，不能用全样本参数泄露。 |
| 股票池 / 币种池 | 必须使用当时可交易范围，不得只保留事后幸存者。 |

每个回测报告必须包含“未来函数审计结论”。如果错误版本明显好于正确版本，优先判定为未来函数或数据泄露风险，而不是策略有效。

## 5. 指标与特征铁律

新特征不得直接进入 Gate。必须先登记、只读记录、消融验证，再讨论准入。

### 5.1 指标登记字段

每个指标至少记录：

```text
指标名称：
公式：
输入字段：
计算窗口：
是否 shift / 滞后：
缺失值处理：
使用目的：
解释方向：
适用周期：
适用模型：
防未来函数说明：
参数候选范围：
消融实验编号：
是否允许进入 Gate / 排序 / sizing：
```

### 5.2 必补特征清单

下列特征是后续趋势策略必须补齐研究账本的候选，不等于允许直接进入实盘。

| 类别 | 特征 | 用途 |
|---|---|---|
| 收益率 | 单根收益率、log return、N 根累计收益、正负收益序列。 | 判断动量、趋势延续和尾部风险。 |
| 波动率 | rolling std、ATR/close、high-low range、真实波幅扩张/收缩。 | 判断行情质量、止损距离和风险预算。 |
| 斜率 | close 斜率、EMA 斜率、MA 斜率、收益率斜率。 | 判断趋势方向和加速/减速。 |
| 成交量 | volume MA、volume ratio、volume z-score、成交量斜率。 | 区分放量突破、缩量回踩和虚假突破。 |
| K 线结构 | 实体比例、上影线、下影线、收盘位置、gap/jump。 | 判断突破质量、反转压力和保护退出。 |
| 趋势质量 | ADX、chop score、均线排列、Donchian 距离、突破后回踩深度。 | 过滤震荡和弱趋势。 |
| 市场状态 | BTC/ETH 锚点、全市场广度、相关性、波动 regime。 | 避免单币信号与大盘环境冲突。 |
| 执行质量 | bid/ask spread、深度、滑点估计、资金费率、OI/拥挤度。 | 判断是否可交易和成本是否吞噬收益。 |
| 风险统计 | 偏度、峰度、尾部亏损、连续亏损、收益集中度。 | 判断收益是否依赖少数极端交易。 |

## 6. 消融法与参数敏感性铁律

消融实验用于回答“哪个条件真的有贡献”，不是为了寻找历史收益最高的组合。

### 6.1 单变量敏感性

一次只能改变一个参数。例如：

- 突破窗口：10 / 20 / 30；
- 成交量阈值：1.2 / 1.5 / 2.0；
- RSI 阈值：60 / 65 / 70 / 75；
- ATR 阈值：1% / 2% / 3%；
- 回踩窗口：3 / 5 / 8 根；
- 止损距离：2% / 3% / 5%。

每次必须记录交易次数、信号数量、扣费后收益、PF、最大回撤、成本占收益比例和样本外结果。只有某一个精确参数表现极好，而附近参数不稳定，默认按过拟合处理。

### 6.2 消融矩阵

每个策略至少比较：

| 实验 | 目的 |
|---|---|
| full gate | 当前完整策略。 |
| 去掉单个指标 | 观察 RSI/MACD/ATR/成交量/方向确认/成本 gate 的边际贡献。 |
| 仅保留核心结构 | 判断策略是否主要来自突破/回踩本身。 |
| 仅保留成本与流动性 gate | 判断是否只是成本过滤制造的表面改善。 |
| 无成本 / 基准成本 / 保守成本 | 判断策略是否经得起真实交易成本。 |
| 当前生产 Gate vs 实验 Gate | 判断新规则是否真的优于现行规则。 |

消融结论必须绑定同一批冻结数据、同一成交假设、同一费用口径和同一训练/验证/测试切分。

## 7. 回测铁律

回测必须可复现、可解释、可审计。

### 7.1 回测输入

回测只能消费下列输入：

- `COMPLETE` 冻结 K 线 manifest；
- 策略卡片版本；
- 指标字典版本；
- 信号状态机版本；
- 成本场景版本；
- 仓位风险版本；
- 执行方式版本；
- 实验编号与参数差异。

### 7.2 回测输出

每次回测必须输出：

- 交易记录；
- 资金曲线；
- 回撤曲线；
- 买卖点；
- 月度收益；
- 交易盈亏分布；
- 成本场景对比；
- 参数结果对比；
- 按模型、方向、币种、周期画像、市场状态、账户切片的表现；
- 失败案例和不可比较样本清单。

### 7.3 必须计算的指标

| 类别 | 指标 |
|---|---|
| 收益 | 累计收益率、年化收益率、月度收益、单笔平均收益、盈利交易平均收益、亏损交易平均收益。 |
| 风险 | 最大回撤、回撤持续时间、年化波动率、下行波动率、最大连续亏损、最大单笔亏损。 |
| 风险收益 | Sharpe、Sortino、Calmar、PF、payoff、胜率、收益回撤比。 |
| 交易质量 | 交易次数、平均持仓时间、换手率、成本占总收益比例、收益集中度、每月交易分布。 |
| 统计 | 均值、标准差、偏度、峰度、自相关、必要时做 t 检验或置信区间。 |

## 8. 样本外与稳健性铁律

参数选择和最终验证必须分开。

| 切分 | 用途 | 禁止 |
|---|---|---|
| 训练集 | 发现参数候选。 | 把训练结果当最终结论。 |
| 验证集 | 检查参数附近是否稳定。 | 验证集反复调到最好。 |
| 测试集 | 参数冻结后只跑一次。 | 测试集不好再回头调参。 |
| walk-forward | 训练窗口向前滚动，测试下一个窗口。 | 使用未来窗口的信息选择当前参数。 |

样本外显著差于样本内时，先检查未来函数、样本量、成本、市场状态和过拟合，不得直接扩大样本寻找好结果。

## 9. 仓位、加仓与组合风险铁律

仓位不是信号强度的简单乘法。

| 概念 | 定义 |
|---|---|
| 止损距离 | 价格反向波动多少触发退出。 |
| 仓位比例 | 投入账户资金的比例。 |
| 单笔账户风险 | 这笔交易最多允许亏损账户资金的比例。 |

风险仓位必须先按 `单笔账户风险 / 止损距离` 计算，再受单品种上限、组合上限、流动性、杠杆、连续亏损和账户状态约束。

加仓必须单独研究，不得等同于重复买入或亏损摊平。任何加仓规则都必须比较无加仓版本、加仓版本、加仓后最大回撤、单笔最大损失、连续亏损和收益波动率。

## 10. 交易成本与执行铁律

真实交易至少包含下列成本：

- 开仓手续费；
- 平仓手续费；
- 买卖价差；
- 买入/卖出滑点；
- 资金费率；
- 市场冲击；
- 合约乘数和最小张数约束。

每次策略报告必须同时展示无成本、乐观、基准、保守四个成本场景。无成本结果只能作为理论上限，不得作为上线依据。

执行方式必须在 `BT-03` 或纸面交易中比较市价、被动限价、条件限价、IOC、一次重报价。未触及限价必须显式过期，不能伪造成交。

## 12. 研究报告准入铁律

任何策略或策略规则申请进入纸面交易、灰度或实盘前，必须产出研究报告。报告必须包含：

1. 策略摘要；
2. 市场假设；
3. 交易品种和数据；
4. 指标定义；
5. 买卖信号；
6. 仓位和风险管理；
7. 成交和交易成本；
8. 回测设置；
9. 绩效结果；
10. 参数敏感性和消融测试；
11. 样本外 / walk-forward 结果；
12. 失败案例和局限性；
13. 结论和下一步计划。

结论只能是三类之一：

- 继续研究；
- 修改后继续；
- 暂停。

不得只写“收益提高，建议上线”。

## 14. 一票否决清单

命中任一项，策略不得进入实盘或不得扩大实盘权限：

1. 冻结 K 线不是 `COMPLETE`；
2. 存在未解释的数据缺口、重复、倒序或异常价格；
3. 指标或信号存在未来函数；
4. 参数调整没有实验编号；
5. 消融实验不能证明新增指标有边际贡献；
6. 成本后 PF、回撤或收益显著恶化但未解释；
7. 样本外或 walk-forward 明显失效；
8. 收益依赖少数极端交易且尾部风险不可控；
9. 交易次数太少，样本量不足；
10. 纸面交易无法复现回测成交假设；
11. 仓位规则绕过单笔账户风险或组合风险上限；
12. 报告没有失败案例和暂停条件。
