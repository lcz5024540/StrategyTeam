# HTX Python R2 P3：候选条件有效性审计

## 1. 结论

P3 已完成。它基于 P2 的不可变候选标签，逐候选重建当时可见的 K 线窗口，并审计
每个研究条件是否真正改变候选集合，以及过滤后的准确率和净期望是否稳定改善。

本阶段没有把任何条件提升为策略门禁，也没有修改 PAPER、LIVE、V4 退出或仓位。
15m 没有条件达到后续研究资格；4h 仅有两个“模型内组合”满足预登记的 P4 研究
资格，仍需在 P4 做完整生命周期、成本、walk-forward 和新 OOS 验证。

## 2. 本阶段修复

旧研究实现存在两个名称与公式不一致的问题：

- `PRICE_SLOPE` 实际为 `close[-1] - close[-3]`，只是两根间隔的端点差；
- `EMA_SLOPE` 实际为 `EMA20 - EMA60`，这是均线价差，不是 EMA 随时间的斜率。

现已建立版本化、无副作用的研究条件库：

| 条件 | 版本 | 实际公式 | 用途 |
|---|---|---|---|
| `ADD_RSI` | `r2-p3-v1` | LONG: RSI14 ≥ 50；SHORT: RSI14 ≤ 50 | RECORD_ONLY |
| `ADD_MACD` | `r2-p3-v1` | MACD histogram 与方向同号 | RECORD_ONLY |
| `ADD_PRICE_SLOPE` | `r2-p3-v2` | `OLS slope(close, 20) / latest close` 与方向同号 | RECORD_ONLY |
| `ADD_EMA_SLOPE` | `r2-p3-v2` | `OLS slope(EMA20 series, 10) / latest EMA20` 与方向同号 | RECORD_ONLY |
| `ADD_REGIME` | `r2-p3-v1` | 本周期 regime 不是 RANGE | RECORD_ONLY |
| score 65 / 70 | `r2-p3-v1` | 模型候选分数达到阈值 | RECORD_ONLY |

斜率只消费信号 K 线收盘时已经闭合的数据；追加未来 K 线不会改变历史结果。旧两根
价格差和 EMA spread 仍以 `deprecated-v1` 保留在诊断结果中，避免把旧公式悄悄解释
成新公式。

## 5. 可进入 P4 的模型内假设

只有以下两个组合同时通过净期望和准确率的稳定性标准：

| Profile / 模型 / 条件 | 基线 → 过滤样本 | 净期望 | 净期望 lift 95% CI | 准确率证据 | 结论 |
|---|---:|---:|---:|---|---|
| 4h Fibonacci + MACD | 94 → 76 | 0.0564U → 0.3667U | [+0.1026, +0.5439] | target-first lift +6.80pp，CI [+3.21pp, +11.31pp]，4/5 窗口为正 | 可进 P4 |
| 4h EMA/VWAP + 价格真实斜率 | 760 → 693 | -0.0357U → +0.0093U | [+0.0003, +0.1025] | 净胜率与 target-first lift 均约 +1.8pp，区间下界为正，4/5 窗口为正 | 可进 P4 |

这两个结果来自已经查看过的开发数据，且是互相重叠的独立候选标签，不是账户级订单
或新 OOS。Fibonacci 的 76 条过滤后样本仍小，EMA/VWAP 的改善幅度也很薄；P4 必须
把它们作为预登记假设单独验证，不得合并叙述为“4h 策略已盈利”。

## 6. 为什么部分条件完全不改变候选

- `ADD_REGIME` 位于候选生成之后，而生产候选本身已经要求 `TRENDING_UP` 或
  `TRENDING_DOWN`，所以候选集中不存在 RANGE，拒绝数恒为 0。
- 生产模型已有结构与确认加分，当前所有已生成候选分数都不低于 70，因此 score 65
  和 70 都不能筛掉候选。
- 旧 `EMA20 - EMA60` 代理与候选方向约束重复，15m/4h 均拒绝 0 条；它既不是斜率，
  也不能提供额外信息。

这些变体已从默认生命周期研究组合中移除，但保留在条件注册和审计结果中作为
`RECORD_ONLY` / deprecated 证据。
