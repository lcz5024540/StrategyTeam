# CoinStrategy 策略总纲 v1 · 趋势 + 套利双引擎

> **结论先行**：CoinStrategy 的策略体系拆成两条主线：**套利策略负责稳定收益和资金底仓利用率，趋势策略负责收益弹性和行情捕捉能力**。资金不能全部暴露在趋势波动里，也不能全部锁在低弹性的套利里；系统需要用统一资金调度、统一风控、统一账本和统一回测实盘评价，把两类策略组合成一个可持续运行的交易系统。

---

## 1. 总目标

CoinStrategy 不是单一交易 bot，而是一个“资金收益系统”。

核心目标分三层：

| 层级 | 目标 | 说明 |
|---|---|---|
| 第一层 | 资金安全 | 控制最大回撤、避免单策略穿仓、避免单账户/单交易所故障导致资金失控。 |
| 第二层 | 稳定收益 | 用套利策略承接一部分资金，追求低波动、可解释、可复利的收益底座。 |
| 第三层 | 收益弹性 | 用趋势策略捕捉上涨/下跌行情，承担可控风险，争取更高收益。 |

系统最终形态：

```text
用户资金
  → 资金分层与风险预算
      → 套利策略资金池：稳定收益底座
      → 趋势策略资金池：行情收益弹性
      → 现金/保证金缓冲池：风控与机会预留
  → 统一执行
  → 统一账本
  → 统一回测与实盘评估
  → 动态调整资金分配
```

## 2. 策略体系分层

### 2.1 一级分类

| 一级策略 | 目标 | 收益来源 | 风险来源 | 资金定位 |
|---|---|---|---|---|
| 套利策略 | 稳定收益 | 资金费、价差、基差、跨市场错配 | 对冲失效、交易所风险、资金费反转、滑点 | 底仓资金，追求稳定。 |
| 趋势策略 | 收益弹性 | 行情方向波动、趋势延续 | 方向错误、假突破、震荡损耗、手续费 | 进攻资金，追求更高收益。 |
| 现金/缓冲 | 风险控制 | 不追求收益 | 机会成本 | 保证金、补仓、故障保护。 |

### 2.2 资金分配初版

资金比例不是固定值，而是随策略质量动态调整。第一版建议如下：

| 资金池 | 初始占比 | 上限 | 下限 | 调整依据 |
|---|---:|---:|---:|---|
| 套利策略资金池 | 50%–70% | 80% | 30% | 套利机会、资金费稳定性、对冲风险。 |
| 趋势策略资金池 | 20%–40% | 50% | 5% | 趋势模型近期 profit factor、回撤、市场分型。 |
| 现金/保证金缓冲 | 10%–20% | 40% | 10% | 市场风险、交易所风险、保证金占用。 |

第一版实盘原则：

```text
套利策略作为收益底座，趋势策略只使用风险预算内资金。
趋势策略表现差时自动降权，不影响套利策略底仓。
套利策略机会不足时，资金进入缓冲池，不强行转给趋势策略。
```

## 3. 趋势策略总纲

趋势策略负责捕捉上涨和下跌行情，也负责识别震荡行情并切换到适合震荡的策略形态。

### 3.1 趋势市场三分法

| 市场状态 | 定义 | 策略行为 |
|---|---|---|
| 上涨趋势 | 多周期向上、市场宽度向多头倾斜、价格结构高点/低点抬高 | 做多趋势策略。 |
| 下跌趋势 | 多周期向下、市场宽度向空头倾斜、价格结构高点/低点降低 | 做空趋势策略。 |
| 震荡市场 | 多周期分歧、箱体明显、ADX/ATR 不支持趋势延续 | 不做趋势追单；可启用网格/区间策略。 |

上涨和下跌本质上是一套“同行情趋势判定”：

```text
上涨趋势 = 多头方向的趋势结构
下跌趋势 = 空头方向的趋势结构
```

因此趋势引擎只需要抽象成：

```text
direction = LONG / SHORT
regime = TREND / RANGE / RISK
```

### 3.2 趋势策略模型

趋势策略第一版采用多模型，而不是单一指标。

| 模型 | 适合市场 | 作用 |
|---|---|---|
| 箱体突破模型 | 横盘后启动 | 捕捉震荡结束后的第一段趋势。 |
| Donchian / 海龟突破模型 | 强趋势启动或延续 | 捕捉高动量突破。 |
| Fibonacci 回踩延续模型 | 趋势中继 | 在趋势回踩后重新转强时入场。 |
| 多周期动量模型 | 小趋势与持续趋势 | 捕捉 15m/30m/60m 共振行情。 |
| 网格/区间模型 | 震荡市场 | 趋势不可交易时，用区间震荡赚波动。 |

注意：网格策略不再作为独立主线无限运行，而是归入趋势体系下的 **震荡市场处理模型**。只有市场被判定为 `RANGE`，且区间边界清晰、波动覆盖手续费时才允许启用。

### 3.3 趋势策略的核心因子

| 因子组 | 代表因子 | 作用 |
|---|---|---|
| 市场分型 | BTC/ETH 多周期、市场宽度、波动状态 | 判断大环境是否适合趋势。 |
| 单币结构 | 箱体、swing high/low、高低点结构 | 判断该币是否有可交易结构。 |
| 多周期方向 | 15m/30m/60m/4h 方向与斜率 | 避免只靠 15m 决策。 |
| 量价确认 | 成交量、成交额、K 线收盘位置、影线 | 判断突破或回踩是否真实。 |
| 波动质量 | ATR%、ADX、chop score | 区分趋势波动和噪音波动。 |
| 位置因子 | 距箱体边界、距 EMA、Fibonacci 回撤率 | 判断是否追高/追空。 |
| 成本因子 | 手续费、点差、滑点、资金费 | 确保预期收益覆盖成本。 |
| 风控因子 | 最大回撤、连续亏损、相关性暴露 | 控制策略失效期。 |

### 3.4 趋势策略输出

趋势策略不直接输出“买/卖”，而是输出标准候选：

```text
symbol
side
model_name
model_score
market_regime
entry_price_hint
invalidation_price
expected_net_after_fee
risk_reward_ratio
factor_snapshot_id
gate_result
reject_reason
```

只有 `gate_result=PASS` 的候选才能进入真实下单队列。

## 4. 套利策略总纲

套利策略负责稳定收益和资金使用率。套利策略必须优先满足“风险可控、收益可解释、对冲完整”。

### 4.1 一级套利类型

| 套利类型 | 说明 | 资金定位 |
|---|---|---|
| 跨所对冲资金费套利 | 在不同交易所建立对冲仓位，赚资金费差或价差 | 稳定收益主力，但交易所和转账风险更高。 |
| 单交易所现货合约对冲资金费套利 | 同一交易所现货 + 永续合约对冲，赚资金费 | 操作闭环更简单，适合作为第一版稳定底仓。 |
| 单交易所合约基差套利 | 利用永续/交割合约基差变化 | 后续扩展。 |
| 价差/统计套利 | 相关币或同币跨市场价差回归 | 后续扩展，要求更强执行与风控。 |

### 4.2 跨所对冲资金费套利

核心逻辑：

```text
选择交易所 A 和交易所 B
比较同一标的资金费率、深度、手续费、可用保证金
在资金费优势方向建立对冲仓位
定期评估资金费是否仍覆盖成本
资金费反转或对冲风险扩大时退出
```

关键因子：

| 因子 | 说明 |
|---|---|
| `funding_rate_diff` | 两交易所资金费差。 |
| `basis_diff` | 两交易所标记价格/指数价格差。 |
| `fee_cost` | 双边开平仓手续费。 |
| `borrow_or_transfer_cost` | 借贷或资金调拨成本。 |
| `depth_capacity` | 可承载仓位规模。 |
| `exchange_risk_score` | 交易所稳定性和提现风险。 |
| `hedge_deviation` | 多空名义额偏差。 |

### 4.3 单交易所现货合约对冲资金费套利

核心逻辑：

```text
资金费率为正：持有现货多头 + 永续空头，赚空头资金费。
资金费率为负：理论上合约多头可收资金费，但单交易所必须具备现货做空/借币/等价反向对冲能力，否则不能自然对冲价格风险。
```

第一版只做正资金费方向：

```text
现货多 + 合约空
```

负资金费方向暂不进入单交易所第一版真实套利，后续放到跨所对冲或具备借币做空能力后再评估。

原因：

| 原因 | 说明 |
|---|---|
| 结构清晰 | 现货抵消合约空头方向风险。 |
| 风险可解释 | 主要风险是基差扩大、资金费反转、现货流动性。 |
| 账户闭环简单 | 单交易所内无需跨所转账。 |
| 适合稳定资金池 | 能作为收益底座。 |

### 4.4 套利策略 gate

| Gate | 拒绝条件 |
|---|---|
| 资金费覆盖 | 预计资金费收益不能覆盖手续费、滑点、基差风险。 |
| 对冲完整 | 现货和合约名义额不能匹配。 |
| 流动性 | 现货或合约深度不足。 |
| 保证金 | 合约保证金不足或爆仓距离不足。 |
| 基差风险 | 合约价格偏离过大。 |
| 交易所风险 | API 异常、提现异常、风控状态异常。 |
| 资金占用 | 收益率低于最低资金占用收益。 |

### 4.5 套利退出

| 退出原因 | 规则 |
|---|---|
| 资金费反转 | 资金费不再覆盖成本。 |
| 对冲偏离 | 现货/合约名义额偏差超过阈值。 |
| 基差失控 | 基差扩大到超过收益保护。 |
| 保证金风险 | 爆仓距离低于阈值。 |
| 收益达标 | 达到目标收益或进入更优机会。 |
| 系统风险 | API/账户/交易所状态异常。 |

## 5. 趋势与套利的资金协同

趋势和套利不能各自抢资金，必须由统一资金调度器管理。

### 5.1 资金池结构

```text
CapitalAllocator
  ├── ArbitrageBucket
  │     ├── CrossExchangeFundingArb
  │     └── SingleExchangeSpotPerpFundingArb
  ├── TrendBucket
  │     ├── TrendLongShortEngine
  │     └── RangeGridEngine
  └── ReserveBucket
        ├── MarginBuffer
        └── OpportunityCash
```

### 5.2 资金调度原则

| 原则 | 说明 |
|---|---|
| 稳定收益优先保底 | 套利策略有高质量机会时优先分配底仓资金。 |
| 趋势策略按表现拿资金 | 趋势模型 profit factor、回撤、胜率达标后提升资金上限。 |
| 单策略不能耗尽资金 | 每个策略有最大资金占用和最大风险预算。 |
| 保证金缓冲不可挪空 | 保留现金/保证金应对波动和补保证金。 |
| 资金按账户隔离 | 多账户体系下，账户级 PnL、风险、手续费率独立计算。 |

### 5.3 动态调仓规则

| 场景 | 调整 |
|---|---|
| 套利机会强、趋势弱 | 提高套利占比，降低趋势占比。 |
| 趋势模型连续盈利且回撤小 | 趋势资金上限逐步提高。 |
| 趋势模型连续亏损 | 趋势资金自动降权，不影响套利底仓。 |
| 市场进入高波动风险 | 降低趋势新仓，保留套利低风险仓位。 |
| 套利资金费收益消失 | 套利资金回到缓冲池，不强行转趋势。 |

## 6. 统一风控

所有策略共享统一风控，不允许单策略绕过。

| 风控项 | 规则 |
|---|---|
| 总账户最大回撤 | 达阈值后暂停新开仓。 |
| 单策略最大亏损 | 单策略触发后降权或暂停。 |
| 单币最大暴露 | 同一币跨策略汇总限制。 |
| 单方向最大暴露 | 全部多头/空头风险汇总限制。 |
| 单交易所最大暴露 | 防止交易所风险集中。 |
| 保证金安全线 | 爆仓距离或保证金率不足时强制降仓。 |
| API 健康 | 行情/下单/查仓异常时进入保护。 |
| 账本一致性 | DB、交易所仓位、订单状态不一致时停止新开仓。 |

## 7. 统一账本与账户体系

多账户、多策略必须从数据库层面区分。

### 7.1 必要维度

| 维度 | 说明 |
|---|---|
| `account_id` | 内部账户 ID。 |
| `account_label` | 展示名称，例如 primary、TradeX。 |
| `exchange` | HTX、Binance、OKX 等。 |
| `strategy_family` | TREND / ARBITRAGE / GRID。 |
| `strategy_name` | 具体策略名称。 |
| `model_name` | 趋势模型或套利模型。 |
| `symbol` | 交易对。 |
| `position_id` | 仓位 ID。 |
| `order_id` | 订单 ID。 |
| `net_pnl_after_fee` | 扣费后净收益。 |

### 7.2 页面展示原则

页面不能简单把 10 个/100 个账号堆出来。应采用：

```text
总览页：全部账户聚合
  → 策略族 drilldown：趋势 / 套利 / 网格
      → 账户 drilldown：单账户表现
          → 策略模型 drilldown：模型级表现
              → 订单/仓位明细
```

## 8. 回测与实盘闭环

任何策略上线前必须经过回测，任何实盘亏损必须能回放。

### 8.1 回测维度

| 维度 | 指标 |
|---|---|
| 总体 | 扣费后净收益、最大回撤、profit factor。 |
| 策略族 | 趋势 vs 套利的收益和回撤。 |
| 策略模型 | 箱体突破、Fibonacci、动量、资金费套利分别统计。 |
| 市场分型 | BROAD_UP、BROAD_DOWN、MIXED、CHOP 下的表现。 |
| 币种 | 单币种胜率、收益、手续费占比。 |
| 账户 | 多账号手续费率和成交差异。 |

### 8.2 实盘观察指标

| 指标 | 说明 |
|---|---|
| 当前资金分配 | 趋势、套利、缓冲各占多少。 |
| 今日扣费后 PnL | 按账户、策略、模型拆分。 |
| 当前仓位 | 策略族、模型、方向、风险预算。 |
| 候选信号 | 为什么开 / 为什么不开。 |
| gate 拦截分布 | 哪类原因导致不开。 |
| 模型表现 | 模型级胜率、PF、回撤。 |
| 套利机会 | 资金费率、对冲偏差、预计收益。 |
| 风控状态 | 是否触发降权、暂停、保护。 |

## 9. 第一版落地路线

### M1：总账本与资金调度骨架

| 任务 | 验收 |
|---|---|
| 定义 `strategy_family` / `strategy_name` / `model_name` 维度 | 趋势、套利、网格可统一入账。 |
| 建立账户维度 | 多账号可独立统计手续费、PnL、仓位。 |
| 定义资金池配置 | 趋势/套利/缓冲资金占比可配置。 |

### M2：趋势策略按新骨架重构

| 任务 | 验收 |
|---|---|
| 因子快照入库 | 每个候选有完整因子。 |
| 多模型候选生成 | 箱体突破、Fibonacci、多周期动量可独立评分。 |
| 统一 gate 和 sizing | 候选通过 gate 后才下单。 |
| 模型匹配退出 | 按 entry_model 平仓。 |

### M3：套利策略恢复为稳定资金池

| 任务 | 验收 |
|---|---|
| 单所现货合约资金费套利重构 | 现货多 + 合约空完整对冲。 |
| 跨所资金费套利规划 | 明确交易所、资金划转、对冲和风控。 |
| 套利收益账本 | 资金费、价差、手续费、滑点独立统计。 |

### M4：统一页面

| 任务 | 验收 |
|---|---|
| 总览页面 | 展示资金分配、总 PnL、风险状态。 |
| 趋势页面 | 展示市场分型、模型候选、仓位和回测。 |
| 套利页面 | 展示套利机会、对冲仓位、资金费收益。 |
| 账户页面 | 支持多账号 drilldown。 |
