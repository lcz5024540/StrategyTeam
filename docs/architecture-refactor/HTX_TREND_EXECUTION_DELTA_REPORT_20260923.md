# HTX 趋势执行链路改造差异与影响报告

> 本报告回答：本轮 `SIG-01 → PLAN-01 → EXT-01 → EXT-02` 完成后，HTX 趋势策略相对 `support_htx@72a0c984` 实际改变了什么、没有改变什么，以及部署后会产生哪些收益、成本和风险。

## 结论

本轮**没有改变真实趋势判断、开仓 Gate、仓位计算、HTX 主动市价单或现有平仓引擎**。它把原本“候选通过 Gate 后直接创建订单意图并发单”的过程，补成了“候选证据 → 冻结价格计划 → 只读 `ENTRY_READY` → 纸面成交校验 → 纸面退出计划”的可审计数据链。

因此，预期影响应分开看：

- 对即时胜率、收益率、真实成交价格：**理论上为零**，因为真实委托类型、开仓价格来源和退出规则没有改。
- 对可解释性、后续限价执行回测和策略归因：**显著提升**，每个组合候选可由 `run_id` 回放到计划与纸面结果。
- 对运行时：通过最终 Gate 的组合候选会增加两份同步快照写入；纸面回传另写一份退出快照和一笔纸面账本。
- 对部署：新增纸面账本表和回传接口；不执行 SQL 时，真实趋势主线通常仍可运行，但纸面成交回传不可用。
- 对完整性：当前价格计划／outbox 记录失败不会阻止真实市价单，意味着极端持久化故障下可能出现真实仓位没有完整纸面证据的情况。这是部署前需要明确接受或收紧的边界。

## 3. 已改变的内容

### 3.1 候选证据从“指标快照”变成“模型解释”

基线已经有 EMA、ATR、ADX、ROC、量能、Donchian、Fibonacci、目标区和 `run_id`。本轮没有把这些因子加权成新分数，而是增加三个解释层：

| 新增证据 | 作用 | 策略影响 |
|---|---|---|
| `TrendState` | 分开记录方向、趋势强度、结构、动量、参与度、市场一致性、衍生品质量和执行质量。 | 只提高归因能力；不改变候选计算。 |
| 模型角色 | 记录主模型、确认模型、冲突证据。 | 可解释“为什么是 Fibonacci”，但不会让 Fibonacci 自动加权或降权。 |
| 同源结构关联 | BOX、Donchian、Fibonacci 描述同一突破—回踩时，以同一相关组记录。 | 防止后续分析将同一结构误称为多份独立 Alpha；当前开仓分数未重算。 |

### 3.2 冻结可执行的价格计划

通过全部现有 Gate 的组合候选现在会生成价格计划，内容包括方向、合约面值、计划张数、触发价、理想价、最差价、TTL、失效价、初始止损、1R／2R、结构目标、预计风险、预计往返成本和扣费后结构目标净 R。

当前的关键限制是：计划是**市场单基线记录**，不是限价规则。其 `orderMode` 明确标为 `MARKET_BASELINE`，并且理想价与最差价都取当前真实开仓基准价。它先解决“当时为什么愿意以这个价格成交”，尚未解决“应该挂在哪个价格等待成交”。

### 3.3 新增只读 outbox 与纸面成交账本

每份价格计划会生成同一 `run_id` 的 `ENTRY_READY`。纸面回传必须同时找到该 outbox 与价格计划，并校验：

- 身份：合约、周期、K 线、policy、`run_id`、`execution_key`；
- 时间：未超过计划 TTL；
- 价格：多头成交价不得高于最差价，空头不得低于最差价；
- 数量：全成必须等于计划张数，部分成交必须小于计划张数；
- 幂等：重复 `execution_key` 拒绝；
- 非成交状态：`REJECTED`／`EXPIRED` 不得携带伪造成交价或数量。

有效回传会新增 `paper-exit-plan-v1` 与 `htx_trend_paper_execution` 一笔账本。该账本是模拟执行证据，不是交易所订单，也不会触发真实平仓。

## 4. 没有改变的内容

下列项目在本轮前后保持一致，不能把新增的证据能力误判为策略收益改造：

| 范围 | 当前事实 | 结论 |
|---|---|---|
| 模型选择 | 仍由数据库启用的组合 policy 选择一个最高优先级候选。 | 没有改为多模型投票、模型组合建仓或概率模型。 |
| 开仓难度 | 最终 Gate 的顺序、阈值和拒绝条件未变。 | 不会因本轮而变得更容易或更难开仓。 |
| 开仓价格 | 多头取盘口卖一，空头取盘口买一。 | 仍是主动成交，不是试探性限价单。 |
| 仓位大小 | 仍使用既有组合名义额与质量／市场宽度 multiplier。 | 没有收紧或放大风险预算。 |
| 真正成交与账本 | 仍由 HTX 订单回查填充真实均价、费用、实现收益。 | 纸面成交不会覆盖真实数据。 |
| 退出引擎 | 模型失效、费用保护后的横盘、横盘亏损控制、ATR trailing、反向信号、资金费成本等保持原逻辑。 | 没有因为 `paper-exit-plan-v1` 改变真实平仓。 |
| 分批止盈与结构止损 | 仍按现有开关控制，默认未因本轮改变。 | 纸面 1R／2R 只是验证和回放素材。 |

## 5. 影响评估

### 5.1 对交易结果

本轮不能承诺胜率、收益率、盈亏比或回撤立即改善。原因是决定这些指标的实时机制——信号模型、Gate、仓位、真实成交方式和退出规则——没有改变。

它能消除的是“开仓后无法说明当时可接受的价格、成本和目标”的信息缺口。积累足够新样本后，才能比较市场单、被动限价、一次重报价等执行方式，并判断是否真的改善扣费后收益。

### 5.2 对可观测性与归因

这是本轮最大的正向影响。完整新样本可以追溯：

```text
候选证据 → 最终 Gate → 价格计划 → ENTRY_READY → 纸面回传 → 纸面退出计划
```

这使后续能够区分四类问题：方向错误、进场价格不佳、退出计划不合理、执行未成交／滑点过大。基线只有候选、成本快照、订单和仓位，难以严谨区分后两类。

### 5.3 对性能与数据库

对每个通过全部 Gate 的组合候选，新增价格计划和 outbox 两次快照记录。现有快照记录器每次会先按 `snapshot_key` 查询，再在不存在时插入，因此正常首次写入增加约两次查询和两次插入；重复扫描命中同键时只查询。

纸面回传还会新增一笔 `paper-exit-plan-v1` 快照和一行 `htx_trend_paper_execution`。这些操作不在 52 币候选扫描的并发行情请求内，而是在少数最终通过 Gate 的候选或外部回传时发生，因此不会放大行情 API 流量；代价主要是数据库 I/O 和 JSON 存储量。

### 5.4 对故障边界

| 场景 | 当前行为 | 影响 |
|---|---|---|
| 候选因子快照失败 | 原有逻辑 fail-closed，组合候选被拒绝。 | 防止没有候选证据的组合单。 |
| 新价格计划／outbox 写入失败 | 记录器吞掉持久化异常；调用方不以返回值阻断真实订单。 | 真实市价单仍可能成交，但对应计划／事件缺失，纸面回放不可完整关联。 |
| 纸面回传表未迁移 | 未调用纸面接口时不影响真实开仓；调用回传会持久化失败。 | 部署后无法积累纸面执行样本。 |
| 纸面回传价格超界、过期、数量不符或重复 | fail-closed，拒绝写纸面账本。 | 防止虚构优于计划的纸面成交。 |

“价格计划／outbox 写入失败仍放行真实下单”是本轮最重要的完整性边界：链路在正常情况下连续，但不是数据库事务级的强一致。若后续要把该链路作为真实执行的强制审计前提，应单独决定是否改为 fail-closed 或使用可靠 outbox 事务。

### 5.5 对部署与接口面

新增表 `htx_trend_paper_execution`、唯一键 `execution_key` 及纸面回传 API。生产部署前需执行 `sql/htx/2026-09-23d__htx_trend_paper_execution.sql`；该 SQL 未执行前，不能将纸面回传功能视为可用。

回传 API 使外部系统能够提交模拟成交，因此发布前还应按现有 Web 安全体系确认调用方认证、授权、审计和限流。本文未对全局安全配置作出结论，不能假设该 endpoint 已具备或未具备保护。

| 部分成交只能消费这对真实快照，并正确重算风险、1R／2R、成本和净 R。 | HTX 真实市场单与纸面成交的长期偏差。 |
| 原始证据、价格计划和 outbox 在回传后保留。 | 市价、限价、重报价三种方式的统计优劣。 |
| 纸面服务没有 HTX 下单客户端依赖。 | 价格计划／outbox 持久化失败时是否应阻断真实下单。 |

## 7. 可复述结论

1. 本轮把趋势系统从“能下单”推进到“能说明一笔候选在什么价格、什么成本和什么风险下值得执行”。
2. 它没有改变模型、Gate、仓位、真实市价下单或退出，因此不应把它当作盈利修复或胜率优化。
3. 新的纸面执行链为限价探路和退出策略回放提供了同源样本，但样本尚未在生产积累。
4. 部署前最需要明确的是：纸面账本 SQL、回传接口的安全边界，以及价格计划／outbox 写入失败时是否允许真实订单继续发送。
