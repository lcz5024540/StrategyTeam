# HTX 趋势策略 MFE 利润保护与可执行退出计划 v1

> 日期：2026-09-25  
> 状态：P0 代码完成，待执行追加式 SQL 与只读部署；不改变真实订单。
> 范围：先覆盖 `FIB_PULLBACK_CONTINUATION / INTRADAY_15M`，再按同一合同扩展至 Donchian 和 EMA/动量。  
> 前置事实：`fib-exit-engine-v3` 已解决 FIB 仓位被旧 FLAT/ATR 链路抢先平仓的问题；它**尚未构成利润保护**。

> **2026-09-30 实施更正**：历史上的 v3 只用于说明演进背景。当前唯一可执行退出链为 `fib-exit-engine-v4`：它直接消费单向持久化的 MFE 保护价，模型失效、利润保护穿越、动态减仓与资金费成本均在 v4 内决策。旧手续费保护、固定分批与 runner 只保留给非 FIB 兼容仓位，不能影响 FIB 的 v4 保护线或提交平仓。

## 1. 要解决的问题

昨天的 ZEC、XRP、LTC、DOGE、SUI 都曾出现扣费后浮盈，却因保护价没有随最高有利价格上移，最终跌回亏损区平仓。现有 v3 的“开仓成本 + 0.15 ATR”仅是保本下限：它能避免一部分已盈利仓位转亏，却不能保留已经产生的趋势收益。

LTC 161 是验收样本：开仓价 `72.92`、12 张、合约面值 `0.10`、最高价 `74.74`、最高净浮盈 `2.1131U`。旧保护价约 `73.1782`，在 `73.14` 才触发时仅预估保留 `+0.1939U`。这不应被定义为利润保护成功。

本计划的目标是把下列链路闭环：

```text
最高有利价格 / MFE
  → 计算新的保护价与可保护净收益
  → 只允许保护价单向收紧
  → 写入不可变证据和仓位状态
  → 同步交易所 reduce-only 条件单或高频触发器
  → 成交、撤销、部分成交回写账本
  → 用 MFE 捕获率和回吐率验证质量
```

不以“最终不亏”作为验收标准；必须同时衡量已实现净收益占峰值净浮盈的比例。

## 2. 设计原则和边界

1. **利润保护与止损不同。** 初始止损、模型失效价控制错误交易；MFE 保护价控制已发生浮盈的回吐，二者不得互相覆盖。
2. **保护价只能向有利方向移动。** 多单只能上调，空单只能下调；服务重启、回撤或因子变弱均不得放松既有保护。
3. **MFE 必须是可审计的成交后口径。** 记录价格峰值、扣费后 MFE、产生时间、当时费率、保护价、预计锁定净收益和实际执行价。
4. **模型决定保护宽度，不决定是否忽略已穿越的保护价。** 高周期同向可使 runner 的保护带更宽，但不能否决已触发的保护退出。
5. **一分钟轮询不是成交保证。** 条件单或高频价格触发负责价格执行；K 线和 15 分钟信号只负责更新趋势证据和保护宽度。
6. **首轮不启用机械盈利即卖。** 只有达到武装门槛后才上移保护；分批减仓需要回吐和转弱证据，不能把所有趋势单变成短线剥头皮。

## 3. 统一的价格和收益口径

### 3.1 基础定义

对多单：

```text
MFE_price = highest_price - entry_price
成本保护距离 = (实际开仓费 + 当前预估平仓费) / 剩余标的数量 + 0.15 × ATR_15m
动态允许回吐 = max(0.40 × ATR_15m, MFE_price × (1 - 保留比例))
MFE 保护价 = highest_price - 动态允许回吐
最终保护价 = max(原保护价, 开仓价 + 成本保护距离, MFE 保护价)
```

空单方向相反，全部计算使用合约张数、面值、实际开仓费和当前账户的平仓费率。`最高净浮盈` 与 `预计锁定净收益` 均必须扣除双边费用；价格计算不能混用未扣费收益。

首轮建议把 `保留比例` 作为配置和回测维度，基线为 `0.50`，而不是写死结论。以 LTC 161 为例：`MFE_price = 1.82`，动态允许回吐为 `max(0.40 × 1.3318, 1.82 × 50%) = 0.91`，MFE 保护价为 `73.83`。在该价附近成交时，扣费后预计保留约 `+1.02U`，即约 48% 的 MFE 净收益。

### 3.2 保护阶段

| 阶段 | 进入条件 | 动作 | 退出条件 |
|---|---|---|---|
| `THESIS_INTACT` | 未达到成本和 ATR 武装门槛 | 只管理初始止损、模型失效和亏损风险 | 达到 `PROFIT_ARMED` |
| `PROFIT_ARMED` | MFE 达到 `max(0.50 ATR, 成本保护距离)` 且净利润覆盖实际成本 | 计算成本保护价并记录武装事实 | 达到 MFE 动态保护门槛 |
| `PROFIT_LOCKED` | 动态保护价能锁住有意义的净收益 | 单向上移保护价，同步执行保护 | 穿越保护价或进入减仓评估 |
| `PROFIT_AT_RISK` | 已锁利，回吐达到噪音带且至少两类转弱证据成立 | 计算目标剩余敞口，提出减仓 | 执行分批、趋势恢复或保护价穿越 |
| `RUNNER` | 部分减仓后趋势仍有正的扣费后延续价值 | 管理剩余仓位的模型专属保护带 | 结构失效、保护价穿越或反转确认 |
| `EXIT_SUBMITTED` | 条件单/高频触发/模型失效发出 reduce-only 委托 | 停止重复下单，等待成交对账 | `DONE` 或人工复核 |

## 4. 实现批次

### P0：真实数据与保护决策落库

**目的**：先让每笔仓位可证明“峰值是多少、应锁多少、为何没有锁住”。不改变任何真实平仓。

- 新增 `ProfitProtectionPlanner`，输入仓位、价格峰值、费用、ATR、结构目标和多周期证据，输出保护价、可保护净收益、MFE 保留比例、允许回吐和建议动作。
- 保护价以仓位持久化字段为权威；每次新峰值只做单向更新。服务重启后从数据库恢复，不等待下一笔新订单。
- `htx_trend_exit_decision` 追加记录：`mfe_price`、`mfe_net_pnl`、`profit_lock_price`、`projected_locked_net_pnl`、`mfe_capture_ratio`、`protection_mode`、`execution_readiness` 与未执行原因。
- 新增不可变 `htx_trend_profit_protection_event`：记录武装、保护价上移、减仓候选、条件单创建/替换/撤销、触发、成交和对账事件。
- 旧 v3 的静态成本保护只保留为最小下限；不得再把它写成完整利润保护。

**验收**：LTC 161、ZEC、XRP、DOGE、SUI 均能生成逐轮保护轨迹；任何一次保护价被放松或历史 MFE 被覆盖均使测试失败。

**2026-09-25 实施状态**：已新增纯 `HtxTrendProfitProtectionPlanner`、仓位侧单向 MFE 保护状态、不可变 `htx_trend_profit_protection_event` 和追加式迁移 `2026-09-25__htx_trend_mfe_profit_protection.sql`。默认 `HTX_TREND_PROFIT_PROTECTION_ENABLED=false`；即使开启也只写 `OBSERVE_ONLY` 决策和事件，不创建、修改或撤销 HTX 委托。LTC 161 单测固定验证 `74.74` MFE 映射为 `73.83` 保护价、预计锁住收益大于 `1U`，且价格回落后保护价不放松。

### P1：本地动态减仓和 runner

**目的**：在趋势转弱时先兑现一部分，不再只有整仓持有或整仓市价平仓。

- 只有 `PROFIT_LOCKED` 仓位进入减仓评估。
- 减仓需同时满足：MFE 已超过最低门槛、回吐超过动态噪音带、至少两类独立转弱证据成立、剩余结构目标的扣费后收益不再覆盖保护价风险。
- `targetRemainingExposure` 由预期剩余净收益与已保护风险决定；按合约张数向下取整，无法形成有效 reduce-only 委托时记录原因。
- 分批成交后按实际剩余张数重算开仓费分摊、MFE、保护价和 runner 目标；未成交或部分成交不得伪造已实现收益。

**验收**：强趋势正常回踩不减仓；LTC 类盈利回撤会至少进入 `PROFIT_AT_RISK`；每次减仓都可解释“保留多少、为何保留”。

### P2：交易所可执行保护

**目的**：消除 60 秒轮询与市价平仓之间的价格空窗。

- 在通用 HTX 客户端补齐“条件单 / 止损止盈委托”的创建、查询、撤销和状态模型；先以 HTX 当前合约 API 文档和小额验证确认 `reduce_only`、触发价、委托价、数量、取消语义与多保护单共存规则。
- 每次上移保护价采用“新单确认 → 旧单撤销 → 对账”的顺序；若新单创建失败，旧保护不得撤销。若 HTX 不允许并存保护单，则以交易所确认的最小无保护窗口方案实现，并留下事故审计。
- 条件单不覆盖模型失效和紧急风险：这些仍可由本地高频价格监听发出 reduce-only 市价平仓。
- 补充独立价格监听器，优先 WebSocket 标记价/最新价；REST 轮询只作为连接降级。它只管理已有仓位和保护执行，不承担 52 币种的入场扫描。

**2026-09-30 v4 实施状态**：v4 已直接用当前交易所标记价判断保护价是否被穿越。若已武装仓位的当前价格穿越保护价，且从 MFE 回吐达到 `1 ATR`，立即提交 reduce-only 全平，不再等待下一根 15 分钟 K 线；仅轻微穿越仍保留完成 K 线确认，避免单次针刺误平。新增默认关闭的 `HTX_TREND_EXIT_SUPERVISOR_ENABLED`：开启后每 `HTX_TREND_EXIT_SUPERVISOR_POLL_INTERVAL_MS`（默认 10 秒）只运行已有仓位管理、退出订单对账和 v4 决策，绝不扫描候选、写因子快照或开新仓，并与完整扫描调度互斥。交易所原生条件单和 WebSocket 触发仍属于后续能力，未伪称已完成。

**验收**：用测试账户最小仓位验证创建、替换、触发、撤销、服务重启恢复和部分成交；任何仓位在保护已武装时都能反查到一条交易所保护状态或明确的 fail-closed 告警。

### P3：回放、对照与灰度

**目的**：证明保护不是以过早卖出换来的表面胜率。

1. 用 1 分钟 K 线和可获得的盘口/成交数据重放 LTC、ZEC、XRP、DOGE、SUI 的实际持仓窗口。
2. 同一开仓、费率、合约面值和滑点假设下比较：旧退出、静态成本保护、动态 MFE 保护、动态 MFE + 分批 runner。
3. 按模型、方向、币种和市场分型输出扣费后净 PnL、PF、平均盈亏比、最大回撤、MFE 捕获率、盈利回吐率、过早退出率和保护穿透滑点。
4. 只有动态版本在足量样本中不恶化 PF 和最大回撤，且显著降低“有利润后亏损平仓”比例，才能进入主账户小仓灰度。
5. 灰度仅主账户；TradeX 保持旧退出作为对照；开关默认关闭且可立即回退。灰度期间每笔成交必须关联保护事件、条件单状态和实际成交价。

## 5. LTC 161 的新验收合同

| 项目 | 要求 |
|---|---|
| 峰值事实 | 持久化 `highest_price=74.74`、`mfe_net_pnl=2.1131U` 与时间。 |
| 保护价 | 动态保护价不低于 `73.83`，且后续不得下调。 |
| 预期锁利 | 在保护价成交的估算净收益约 `+1.02U`，不能再把 `+0.1939U` 判为通过。 |
| 穿越处理 | 保护价穿越时，由统一退出负责人触发；不得回落旧 FLAT/ATR。 |
| 成交真实性 | 回放以首次可执行 1 分钟价格和保守滑点计算；实盘以交易所成交回报为准，不能用触发价伪造成交价。 |
| 保护质量 | 输出 `已实现净收益 / MFE 净收益`、保护穿透滑点和未锁利原因。 |

## 6. 配置与开关

建议新增以下独立配置，默认均为只读或关闭：

```text
HTX_TREND_PROFIT_PROTECTION_ENABLED=false
HTX_TREND_PROFIT_PROTECTION_LIVE_ENABLED=false
HTX_TREND_PROFIT_MFE_LOCK_RATIO=0.50
HTX_TREND_PROFIT_PROTECTION_NOISE_ATR_MULTIPLIER=0.40
HTX_TREND_PROFIT_PROTECTION_CONDITIONAL_ORDER_ENABLED=false
HTX_TREND_PROFIT_PROTECTION_PRICE_WATCHER_ENABLED=false
```

`HTX_TREND_EXIT_ENGINE_*` 仍控制 FIB 仓位的退出负责人；上述开关只决定 MFE 保护是否产生真实减仓/保护订单。两类开关必须在决策记录中分别写出，避免再次出现“新引擎观察、旧链路真实下单”的责任不清。

## 7. 不在本轮处理的事项

- 不把所有趋势模型直接迁入新保护参数；Donchian、EMA/动量必须先积累同口径 MFE 与回吐样本。
- 不以固定 1R、固定 33% 或“盈利即平”替代动态保护。
- 不在未完成条件单语义验证前宣称轮询市价单能保证保护成交价。
- 不部署、不启用真实 MFE 保护、不调整账户风险或杠杆。
