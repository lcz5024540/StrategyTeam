# HTX 趋势三阶段判断与可观测性执行计划 V1

## 目标

把趋势策略从“开仓时一次判断、平仓时临时解释”改为可回放的连续判断链。每笔候选和持仓都必须能回答：当时为何认为有趋势、持有期间趋势何时转弱、趋势变更为何导致保护、减仓或退出。

本计划先建设数据与证据，不直接放宽开仓 Gate，也不改变 v4 真实退出动作。所有生产 SQL 均为追加式迁移，由发布前人工执行；服务启动继续保持 `spring.sql.init.mode=never`。

## 统一口径

| 术语 | 含义 | 允许驱动的动作 |
|---|---|---|
| `ENTRY_ASSESSMENT` | 某个候选在开仓前的模型、结构、多周期和执行质量证据 | Gate、候选排序、仓位 sizing |
| `HOLDING_ASSESSMENT` | 某个已开仓持仓在一根完成 15m K 线后的实时趋势重评 | 持有、保护价收紧、进入观察状态 |
| `TREND_TRANSITION` | 两次持仓评估之间的状态变化，例如 `TRENDING → WEAKENING` | 为退出引擎提供明确的状态事件 |
| `TRENDING` | 入场方向、EMA、动量及高周期未出现实质冲突 | 继续持有；保护价仅可单向收紧 |
| `WEAKENING` | 当前趋势减弱，但尚未满足失效或反向确认 | 评估剩余净收益、回吐与动态减仓 |
| `INVALIDATED` | 模型失效、反向信号，或多周期与市场环境确认反向 | 全平候选；由现有 v4 风控执行 |

历史盈亏、PF、胜率只用于报告和研究归因，禁止进入当前候选的趋势评分、Gate 或仓位倍率。

## 批次 0：运行时 K 线证据可靠性

**状态：代码完成，本地提交 `6d32f8ab`，未推送、未部署。**

- 将运行时 K 线证据写入从并发大批量写入改为单写入通道。
- 每批最多 32 根 K 线；MySQL 死锁最多重试 3 次。
- 最终写入失败保持 fail-open，不得阻断候选扫描或下单。
- 验收：连续扫描中无未重试的 deadlock；K 线窗口、快照和计算 run 可完整关联。

## 批次 1：三阶段评估账本

新增追加式迁移与不可变 `htx_trend_assessment` 账本，字段至少包括：

- 关联：`assessment_key`、`run_id`、`position_id`、账户、合约、方向、主模型、周期画像、完成 K 线时间。
- 状态：`assessment_stage`、`trend_state`、`previous_trend_state`、`transition_type`、`transition_reason`。
- 市场证据：15m/30m/1h/4h/1d 信号、EMA 相对位置、ADX、ATR、ROC、结构位置、市场广度、BTC/ETH 锚点。
- 交易证据：入场价、参考价、失效价、目标区、预期 R、当前净收益、MFE、MAE、回吐、保护价。
- 追溯：因子快照、运行时 K 线窗口、引擎版本、原始证据 JSON。

写入规则：

1. 每个组合候选在最终 Gate 前写一条 `ENTRY_ASSESSMENT`；Gate 通过、拒绝和执行预检失败均更新为独立不可变结果，不覆盖原记录。
2. 每个活动仓位在新的已完成 15m K 线出现时写一条 `HOLDING_ASSESSMENT`；同一 `position_id + bar_time` 幂等。
3. 当趋势状态、方向确认、保护模式或有效结构发生变化时额外写 `TREND_TRANSITION`；无状态变化不伪造转换事件。
4. 账本写入失败只告警，不阻断现有策略路径；但必须带可检索的结构化日志。

验收：任一真实订单可从订单反查入场证据、逐 K 线持仓状态和全部状态转换；服务重启后不重复写同一完成 K 线。

## 批次 2：结构化日志与数据质量监控

- 统一日志键：`runId`、`positionId`、`account`、`contract`、`model`、`timeframeProfile`、`assessmentStage`、`trendState`、`previousState`、`transitionReason`。
- 候选扫描日志必须区分：无信号、模型候选、趋势状态拒绝、盘口/资金/保证金/窗口拒绝、真实下单成功或交易所拒绝。
- K 线取证记录成功率、死锁重试次数、窗口完整度和落库延迟；缺数据标为 `PARTIAL`，不得伪装为完整样本。
- 验收：一轮 52 币扫描可统计每种拒绝原因和每个阶段的写入成功率。

## 批次 3：趋势质量分析与回放

基于同源账本与冻结 K 线，按 `模型 × 方向 × 市场状态 × 周期画像` 生成：

- 入场后先到 `+0.5R`、`+1R`、结构目标或失效价的比例；
- MFE、MAE、回吐、持仓时长、状态转换次数；
- `TRENDING → WEAKENING` 后恢复、减仓、失效的条件分布；
- 扣费后净收益、PF、平均盈亏比、最大回撤与样本量。

回放只使用冻结 K 线、实际费率和同一执行假设。数据集非 `COMPLETE` 时输出 `INSUFFICIENT_EVIDENCE`，不得用来调整实盘参数。

## 批次 4：退出引擎基于证据的灰度

仅在批次 3 有足量完整样本后进行：

- v4 退出引擎读取 `HOLDING_ASSESSMENT` 与 `TREND_TRANSITION`，不再从零散临时变量推断趋势。
- 先只读记录建议动作；主账户小仓灰度；TradeX 保持对照，直到镜像接口稳定。
- 验收比较旧路径与新路径的扣费后净 PnL、PF、MFE 捕获率、盈利回吐率、过早退出率和最大回撤。
