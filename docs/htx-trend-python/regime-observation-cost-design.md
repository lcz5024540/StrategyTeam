# A/B 样本观察与实际成本对账

日期：2026-11-05；基线：`199e8742`；状态：已实现并本地验证，未部署；读者：策略、研发、测试。验收见[交付报告](regime-observation-cost-20261105.md)。

本次增加两条旁路：一条说明训练样本是否完整、三档在同一批机会上的表现；另一条说明每个仓位的计划成本与已发生成本有何差异。两条旁路均只输出证据和告警，不参与开仓准入、不改ATR排序或持仓退出。新开仓通过显式配置开启，不把安装包等同于真实账户运行授权。

## 已确认规则

- 用户否决快照生命周期改造；不加快照过期、定时训练或自动替换。
- 用户确认样本检查和成本对账“不阻止新开仓”。不加完整率、成本偏差拒单阈值；不降低已有正净收益、账户、行情、授权和贝叶斯证据门。
- 选中的ATR在成交后冻结；旁路结果不能重选、改止损、扩大仓位或触发交易。
- 费用/资金费缺失为未知，不以数据库默认0或当前资金费率冒充真实结算。
- 不合并、不推送，不自动启动真实资金账户。可交付入口已开启的显式配置并进行受控PAPER运行；LIVE启动由账户持有人执行。

## 样本完整性与三档同机会比较

### 分母和排除原因

按场景、时序、成本实验分组，分别列每档唯一机会总数、完整成熟数、未平/删失/未知费用/未成熟/重叠排除数。重复记录不增加分母。同组存在一个机会而其他档缺记录时，显示缺档，而不是把缺档收益视为0。

完整率表示“进入统计的成熟结果 / 唯一机会”，不是盈利概率。没有机会时返回null。观察提示包括缺结果、三档样本集合不同、共同样本不足和缺失旧观察元数据；不使用臆造的完整率阈值。

### 同机会配对

以同场景、时序、成本身份下的`opportunity_id`连接三档；要求合约与入场时间一致，只有三档均已成熟且通过原统计过滤的机会进入共同集合。输出三档共同样本均值、两两净收益差、共同时间块数、集合摘要和排除数。原各档均值仍保留；配对结果不替换现有选档输入。

配对只减少样本集合不同造成的误导，不声称消除删失偏差。即便共同集合结果为正，也不构成新的实盘准入。

### 与运行时、回放的关系

快照携带只读观察摘要，选档证据可展示相关摘要但不能用它改`allowed`或`ranked_exits`。报告显示原统计与配对统计。训练继续禁止UNSEEN/PROTECTED；未来标签不进入统计，离线回放继续按冻结协议执行。观察字段全部采用整数、布尔和十进制字符串，避免MySQL JSON改变证据哈希。

## 计划与实际成本对账

### 冻结计划成本

在A/B持仓上下文追加独立`cost_plan`，记录每单位计划入场手续费、目标/止损退出手续费、入场参考价/限价、冻结目标/止损、滑点预算、合约面值、计划合约数与证据引用。未来资金费预算保持null。该对象不回写原风控参数；旧仓缺对象时输出`PLAN_UNAVAILABLE`。

### 实际数据及金额口径

逐仓读取完整入场与平仓订单收据，以稳定订单ID去重；不根据数据库fee默认值推定成本。按实际成交量计算VWAP，部分成交的计划成本按成交量缩放。费用统一USDT，正数表示费用支出，负费用表示返佣。实际资金流水正数表示收入，负数表示支出。

- 入场滑点成本 = 方向符号 ×（实际入场VWAP − 触发参考价）× 实际入场单位数。
- 已平部分毛损益 = 方向符号 ×（平仓成交额 − 入场VWAP × 已平数量）× 合约面值。
- 已平净损益 = 毛损益 − 已平仓手续费 − 按已平比例分配的入场手续费 + 已归属资金流水。
- 每腿手续费偏差按相同实际成交量比较计划与实际；退出价既可能止盈也可能止损，不能把未达到目标的行情损益错误称作滑点。退出滑点仅在有相应平仓订单参考价时计算，否则标未知。
- 尚未平仓部分不冒充已实现利润，不新增mark-to-market策略决策。

### 资金费覆盖与归属

复用现有只读资金费分页接口，必须有完整覆盖区间和终端空页证据。按账户/隔离合约及真实入场、平仓时间限定区间；有其他重叠仓位、缺精确时间、分页未完成或币种不符时返回UNKNOWN。只有完整覆盖且没有流水，才可记0。非空交易所合约流水无法仅凭本地仓位表排除手工/外部交易，因此自动读取器保留流水但不标为已归属；本地重算输入只有明确证明`ownership_verified`后才可分配。资金费前净损益独立展示，不因结算查询失败而丢失已验证手续费与成交信息。

对账是累计事实的重新投影，而非在旧汇总上累加，重复运行/重启不会重复计费。迟到成交或资金费到达后生成新版证据，保留此前未知状态，不修改历史证据。

### 运行接入与告警

观察结果统一含`observation_only=true`、`affects_entry=false`、状态、缺失原因、差额和证据身份。有正向成本超支、数量不一致或未知字段时输出结构化warning。无任意“过大”阈值：差额完整呈现，成本支出超出冻结预算即作为提示，不触发交易动作。

PAPER从本地持仓/成交台账投影，清楚标为模拟费用；没有结算覆盖的资金费仍未知。账户回放结束再投影一次，确保末次平仓包含在`cost_observations`。LIVE使用独立后台只读连接，网络/DB读取不在价格止损循环等待，也不能把异常加入worker的`failures`。每60秒尝试调度一批、最多10仓，轮转扫描持久计划关联仓位，覆盖已闭仓，不只查活跃持仓；全量轮转末尾有一次空批次重置游标。失败写旁路错误；下一次可重试。证据保存仍用现有本地证据库，不承诺硬实时延迟。

## 显式开启新开仓

复用`HTX_RT_ENTRY_ENABLED=true`。发布工具支持`--enable-regime-entry`显式开启A/B入口，并验证配置、env与manifest一致；其他策略和未显式开启的构建保持原行为。包内仍标`NOT_ELIGIBLE`，不生成或伪造LIVE授权。启用入口不等于每次触发必有订单：原信号、贝叶斯、成本、账户和执行门仍生效。
