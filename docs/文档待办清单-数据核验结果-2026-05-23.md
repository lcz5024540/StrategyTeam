## 2. 代码事实核验

### 2.1 `countPendingSignals()` 不是硬编码 0

`CapitalRecycleExitService.countPendingSignals()` 当前逻辑：

- 注入可选 `SmartWalletFollowTaskMapper`。
- 查询 `smart_wallet_follow_task` 中 `status='PENDING'` 且 `created_at >= now - lookbackHours` 的数量。
- `lookbackHours` 默认 24，可由 `smart-wallet.signal-risk.pending-signal-lookback-hours` 覆盖。
- mapper 缺失或查询异常时才返回 0。

结论：文档中“硬编码 0”的说法已过时，应改成“真实查询，失败时 fallback 0”。

### 2.2 `SmartWalletController` 存在位置

真实文件：

`coin-strategy-job/src/main/java/com/metaverse/coin/strategy/job/smartwallet/controller/SmartWalletController.java`

Web 模块中则是更细粒度的 Controller 拆分，例如：

- `SmartWalletAuditController`
- `SmartWalletReadController`
- `SmartWalletSettlementController`
- `SmartWalletFollowTasksController`
- `SmartWalletPositionWriteController`

结论：`POLYMARKET_ARCHITECTURE_ANALYSIS.md` 中“找不到 SmartWalletController”的段落应删除或改为“job 模块存在，web 模块已拆分本地 BFF Controller”。

### 2.3 funding-rate 风控类名

代码中真实类名：

`coin-strategy-core/src/main/java/com/metaverse/coin/strategy/core/arbitrage/risk/SingleExchangeRiskService.java`

未发现 `SingleExchangeRiskController` 生产类。`funding-rate/FUNDING_RATE_ARBITRAGE_SINGLE_EXCHANGE_SHARE.md` 等文档中的 `SingleExchangeRiskController` 应统一改为 `SingleExchangeRiskService`。
