# 问题记录目录 — 索引与归档约定

本目录存放 Polymarket 跟单策略的**问题记录 / 巡检快照 / 根因分析 / 修复方案**。文件较多，遵循以下生命周期约定管理，避免无限膨胀。

## 归档约定（lifecycle convention）

每条问题记录有「待解决 / 已修复」两态。约定如下：

1. **命名即状态**：文件或目录名中以 `待解决` / `已修复` 标识当前状态。
2. **全部待解决项修复后转归档**：当某条问题记录（独立 `.md`，或「`README.md` + 诊断脚本」目录）中登记的**全部待解决问题都已修复并验证**时：
   - 将该 **目录 / 文件** 重命名为 `…-已修复-YYYY-MM-DD`；
   - **保留对应的 README / 报告正文**，但将其内容（或在顶部加横幅）改为「✅ 已修复」摘要：原问题 → 根因 → 修复 → 部署/验证状态；
   - **删除对应的诊断脚本（`*.py`）与一次性日志（`*.log`）**——这些是当期取证用、已无复用价值。
3. **残留未结项不丢失**：若快照中部分项已修复、个别项仍开放，则残留项须并入**当前活跃巡检日志**继续跟踪，归档说明中注明指向。
4. **巡检日志的特殊性**：每日巡检快照常累积引用同一演化中的问题簇。只有当某快照的**主阻塞问题已部署+实测验证**、且残留项已转入活跃日志时，方可归档；仍含开放阻塞（如服务器不可达 P0-0）的最新快照保持 `待解决`。
