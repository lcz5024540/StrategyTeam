# 全盘风险审计（量化产品视角）2026-06-03

> 目标：跳出"跟单工具"，按**量化交易产品**的标准全盘审视代码风险——资金安全、风控熔断、并发一致性、执行/结算完整性、alpha 衰减。
> 说明：P0-2(Kelly/EV)、P0-3(negRisk) 按你的要求暂放，仅在末尾列出占位。下面**重点是你没提到、但对一个量化产品同样致命**的风险。
> 严重度：**P0=可致大额/无界/静默亏损**，**P1=显著拉低盈利或埋雷**，**P2=次要**。证据均含 file:line。

## 一、风控与熔断（最缺的一块，P0）

### R1【P0·MISSING】没有"组合级总闸"：日亏/回撤/连亏只告警、不停手
- `StrategyAlertService.java:135-142` 检测全局日亏超限后只 `fireAlert(DAILY_LOSS_LIMIT)`——**只发告警，不暂停任何交易**。
- 在整个 smart-wallet 跟单/执行链路里 **搜不到任何 halt/killSwitch/日亏/回撤 的执行前置判断**（grep `killSwitch|isHalted|maxDailyLoss|globalRisk|StrategyEngineFlag` 于 smartwallet 包 = 空）。`AlertType.KILL_SWITCH` 存在但**没接进开单路径**。
- smart-wallet 的 `maxDrawdownRate/maxDrawdown` 只是**筛选 leader**的门槛（拒绝高回撤的对手），**不是我们自己账户的回撤熔断**。
- **影响**：策略亏损时**没有任何自动刹车**，可一路放单到资金耗尽（`availableCapital<=0` 才停，那已是地板）。量化产品必须有：日亏上限、账户回撤上限、连续亏损/连续失败熔断，触发即**自动停开新仓**（可保留平仓/结算）。
- **建议**：在开单执行入口加一道 `G0_RISK_HALT` 门，读一个可热切的熔断状态（日亏、滚动回撤、连亏、错误率），命中即拒新开仓并告警；熔断状态由健康监控作业写入 `strategy_engine_flag`。

### R2【P0·MISSING/RISK】关键风控门"默认关闭"，靠 DB 配置兜底——配置缺失即裸奔
- 多个保护门默认 false 且只能靠 `strategy_runtime_config` 打开：净 EV 门 `enableProfitabilityGate`、深度门 `enableDepthAwareSizing`、G6c 空 ask 门、leader 滚动门等（`SmartWalletProperties` 默认值）。一旦换环境/DB 行缺失，**系统是"不设防"地交易**。
- 之前实测的「事件同步停 16h → 零开单」「快照表长期空 → 开单退化为现价」就是这种"静默失效无人知"的典型。
- **建议**：把"安全相关"门的默认值改为**fail-safe（默认开/保守）**；启动时对关键配置做校验，缺失/危险值直接拒绝启动或强制保守；并补监控（见 R3）。

### R3【P0·MISSING】无"交易健康"监控告警（静默故障）
- 没有对：事件摄取滞后、连续 N 分钟零开单、结算积压、可用资金见底、错误率飙升 的实时告警。`StrategyHealthMonitorJob` 未覆盖这些。
- **影响**：16 小时停摆是事后靠人翻日志才发现的。量化产品的"哑火/失真"必须分钟级报警。
- **建议**：补 5 类告警（摄取延迟>5min、零开单连续时长、结算 backlog、资金利用率、error 速率），落 `strategy_alert` 并外发。

## 二、资金与敞口完整性（并发/超额，P0）

### R4【P0·BUG】"在途资金"不计入可用资金 → 超额配置
- `availableCapitalUsdc()`（`SmartWalletAccountingService.java:1118-1133`）只减**已成交持仓**的 `costBasisUsdc`（`isCapitalLockedPositionStatus`）。
- **PENDING/EXECUTING 的跟单任务**（已批准、已定 stake）和**已挂未成交的 LIVE 订单**（只写了 `smart_wallet_order`、无 position、无 ledger 成本，`recordExecution` 在未即时成交时 `:222-230` 提前返回）**都看不到**。
- **影响**：每个待执行任务/挂单都按"全额 bankroll"算可用资金 → N 个待成交信号各自对同一笔钱定仓，**累计承诺资金可远超 `maxTotalOpenCostUsdc`**；`min(liveWalletBalance)` 兜底只在 USDC 真正离开钱包后才生效，滞后于挂单。
- **建议**：`availableCapitalUsdc()/totalOpenCostUsdc()` 扣减 PENDING/EXECUTING 任务的 `recommendedStakeUsdc` 与未成交订单的名义额。

### R5【P0·BUG】G4 资金门"读—判—开"非原子，无锁 → 并发突破上限/透支
- `SmartWalletSignalRiskService.java:373-389` 的总成本门/可用资金门是纯读后判断；唯一并发原语 `claimTaskForExecution`（`SmartWalletFollowTaskService.java:523-529`）只防"同一 task 重复执行"，**不护跨任务的资金不变量**。
- `processPendingTasksNow()/executeTaskNow()` 等多入口、多实例下，两个任务可在彼此持仓成本落库前都过 G4 → 双开，突破 `maxTotalOpenCostUsdc` 与 bankroll。
- **建议**：资金预留做成原子（`UPDATE ... SET reserved=reserved+? WHERE budget-reserved>=?` 命中即预留）或组合级锁包住"读—判—提交"，并把预留计入 `totalOpenCostUsdc()`。

### R6【P0/P1·RISK】无持仓数硬上限、无品类/事件/相关性硬上限（集中度风险）
- `maxOpenPositions` 已在开单处**硬移除**（`@Deprecated`，仅用于展示/退出打分，`SmartWalletProperties:755-762`）；现仅有 `maxTotalOpenCostUsdc`、`maxPerMarketUsdc(200)`、`maxPerFollowWalletUsdc`（`FollowExposureLimitService`）。
- **缺**：按**品类**、按**事件**（同一事件多市场）、按**相关性簇**的硬上限。唯一的相关性信号 `countCorrelatedOpenPositions`（`:2507`）只是"共享 token 词"的粗启发式，且只**软性降 stake、不能拒单、不封总额**。
- **影响**：组合可被高相关赌注灌满（同一赛事多腿、同主题多子市场各自顶到 per-market 上限），实际敞口远超表面分散度——量化产品的尾部风险来源。
- 且 R4/R5 的"在途不计入"同样让 per-market/per-leader 上限被并发/挂单瞬时突破（`FollowExposureLimitService:175-196` 只数 `OPEN` 的 trade_order）。

### R7【P1·RISK】replay/并发"双开"：去重是 TOCTOU、无唯一索引
- 事件去重（`recordTradeEvent` 先 select 后 insert，`SmartWalletFollowTaskService:124-150`）、任务去重（`:813-825`）都是"读—判—写"，**无 DB 唯一约束**。重启后 WS backlog 重放/并发可双插 → 同一 leader 成交被跟两次、资金花两次。
- **建议**：`smart_wallet_trade_event(source, external_trade_id)`、`smart_wallet_follow_task(source_event_id)` 加唯一索引，靠插入冲突而非读后写。

## 三、定价/成交真实性（部分已修）

### R8【P0·已修】纸面开仓/平仓不按真实盘口 → 纸面胜率/收益虚高
- 已修：纸面开仓套用滑点、纸面止盈止损按真实 bid 成交（本轮 P0-1，已编译通过，待部署）。
- **未修**：**跟随 leader 平仓的纸面价仍按 leader 成交价** `event.getPrice()`（`FollowPositionAdjustmentService.resolveExitPrice:760`），不是本账户 bid → 在最关键的"跟随退出"上仍虚高。建议 PAPER 路径改用本账户盘口 bid。

### R9【P1·RISK】盘口快照来自 ~45s 轮询，且 maker/taker/深度三处 staleness 阈值不一致(30s/60s/300s)
- 限价定价用的是 DB 快照（`PolymarketOrderRequestFactory.fetchBestBid/Ask` 读 `smart_wallet_market_snapshot`），而 `markToMarket` 用实时 CLOB——**两套口径不一致**，快进快出市场里限价可能锚在 0.5~5min 前的旧价 → 漏成交或更差成交。建议限价也走实时盘口、统一 maxAge（≤10s）、开 WS 热路径。

## 四、leader 质量 / alpha 衰减（量化核心）

### R10【P1·已修】leader 胜率分母含平局，低估真实胜率 → 误拒好 leader（本轮已修）

### R11【P1·RISK】allowlist 绕过近期/冷却/leader 盈利门，只打日志不降权
- `SmartWalletSignalRiskService:159-164, 660-677`：allowlist 钱包在 observe 冷却中/当前持仓不盈利仍放行。allowlist 入选时快照质量、保留 30 天，期间 leader 转坏照跟。建议冷却期至少降仓、周度刷新重算近期表现。

### R12【P1·RISK】存在第二条弱门控的 LIVE 执行路径
- `SmartWalletFollowService.executeSignal`（controller 可达，可 LIVE）只做 `buildSignal` 弱检查，**不走** 主风控（冷却/drift/leader 盈利/净 EV）。建议下线或收口到主门控。

### R13【P1·RISK，alpha】leader 选择 = 选"过去的赢家"，幸存者偏差/过拟合
- `WeeklyTopLeaderAutoAllowlistJob` 按 `winRate` 排序取 TOP N（有 `minLifetimeTrades` 样本下限排除单笔暴富，但**无统计显著性/样本充分性检验、无样本外验证、无多重检验校正**）。预测市场里小样本高胜率大概率是运气。
- 缓解项已有：30 天过期 + PAPER 模式 + `stake_multiplier 0.5`。但**真要转实盘**前应加：最小决断样本（如≥50）、胜率置信下界（Wilson 下界而非点估计）、近端 vs 历史一致性、去重同一实体多钱包。

### R14【P1·RISK，alpha】复制延迟 → 逆向选择
- 信号链路：事件摄取（曾滞后数百分钟）+ 30s 同步 + 多门控，到我们下单时价格可能已离 leader 成交价较远。`max-signal-age-seconds=3600` 太宽（1h 前的信号仍可跟）。入场用 best-ask 取价（`resolveFreshEntryPrice`），但**没有"相对 leader 成交价的最大滑移"硬门**——可能在 leader 之后买在明显更差的价位。建议：收紧信号新鲜度（如≤数分钟）、加"vs leader 价最大偏离"拒单门。

### R15【P2·RISK，alpha】leader 退出跟随依赖事件抓取
- leader SELL 走 `DYNAMIC_FOLLOW_EXIT` 会跟随平仓（正确）；但若 SELL 事件漏抓/延迟，且 allowlist 仓位又被排除在自动止损外（见 R16），则只能扛到结算，edge 反转。

## 五、结算 / 持仓 / 出场（部分已修）

### R16【P1·RISK】allowlist 仓位被排除在"所有自动出场"之外 → 你最信任的仓位没有止损
- `SmartWalletPositionSyncService.filterOutAllowlistPositions` + `CapitalRecycleExitService` 把 allowlist 来源的仓位从止损/止盈/回收**全部剔除**，一路扛到结算。请确认是否有意；建议至少保留尾部止损。

### R17【P1·RISK】资金回收死区偏正(+0.08) → 砍掉"慢热的赢家"
- 死区 `[-0.05,+0.08]` + 持仓 8h 即可被回收，+7% 且在涨的长线赢家会被按当前 bid 卖掉，放弃奔向 1.0 的上行。建议死区上沿收到 ~0.02 或对"正收益且趋势向上"豁免。

### R18【P0·已修】已结算市场订单卡 OPEN（本会话已修：本地权威结算 + 坍塌即亏损结算，已部署）

### R19【P1·MISSING】无对账（本地账 vs 链上余额），无未认领资金核算
- 未发现"本地 position/cash 合计 == 链上钱包余额"的对账/漂移检测；`RESOLVED_UNCLAIMED` 的未认领赢利是否计入资金、claim 的 gas 成本如何核算，缺乏闭环。量化产品必须有日终对账。

## 优先级总览（建议落地顺序）
1. **R1 组合级熔断总闸**（日亏/回撤/连亏自动停开新仓）——量化产品的底线，目前完全缺失。
2. **R4+R5 在途资金计入 + 原子资金预留**——杜绝超额配置/透支/突破上限。
3. **R6 集中度硬上限**（持仓数/品类/事件/相关性）——控尾部风险。
4. **R2+R3 安全门默认 fail-safe + 交易健康监控**——杜绝静默失效裸奔。
5. **R8(剩余)+R9 成交真实性**、**R16+R17 出场**、**R11/R12 leader 门收口**。
6. **R13/R14 alpha**（leader 选择统计严谨性 + 复制延迟/偏离门）、**R7 唯一索引防双开**、**R19 对账**、**R20 订单对账**。
