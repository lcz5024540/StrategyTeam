> 范围：`coin-strategy-job/.../smartwallet/service/`、`coin-strategy-common/.../sizing/`。
> 严重度：**P0=直接亏钱/严重失真**，**P1=显著拉低胜率或盈利**，**P2=次要/偶发**。

## 一、直接回答你提的三个疑问

### 1) 模拟开单「没有按真实订单簿处理」——✅ 属实（P0）
- **开仓**：纸面成交价 = `signal.getMarket().getPrice()`（`LoggingPolymarketExecutionGateway.java:159`），状态直接置 `FILLED`，**零滑点、不吃深度**。该价虽来自盘口 best-ask（`resolveFreshEntryPrice`），但等于假设「整笔 stake 全部在 best-ask 一档成交」。
- **平仓（止盈止损）**：纸面平仓价 = `costBasis*(1±threshold)/qty` = **正好等于触发阈值价**（`SmartWalletPositionSyncService.resolvePaperThresholdExitPrice:1033-1055`），不看真实 bid、不看深度。
- **跟随 leader 卖出平仓**：纸面平仓价 = **leader 的成交价** `event.getPrice()`（`FollowPositionAdjustmentService.resolveExitPrice:760-769`），不是本账户能成交的 bid。
- 讽刺的是：项目里**已经有**一个高质量的「按 1c/3c/5c 分档 VWAP + best bid/ask」的盘口成交模拟器 `ShadowFillSimulationService`，但它**只喂给影子账本** `smart_wallet_signal_shadow`，**没有用于真实纸面仓位**（`SignalShadowRecorder` vs 上面的 gateway 路径）。
- **影响**：纸面 PnL/胜率系统性偏乐观——开仓不付滑点、止损「干净」成交、止盈「恰好」命中、跟随平仓按 leader 的好价。**你看到的纸面胜率/收益不能代表实盘**，而且基于纸面去标定门槛/仓位会被带偏。
- **建议**：纸面开仓/平仓改为走 `ShadowFillSimulationService`（按 stake 真实吃盘口分档 VWAP）或至少用 `position.getLastMarkPrice()`（已是实时 bid）作为平仓价；杜绝用「leader 价 / 阈值价」记账。

### 2) 跟单地址「没判断对手胜率/质量」——⚠️ 主链路有判断，但有真实缺陷
主链路（链上监控触发）**确实**对 leader 做了胜率/PnL/回撤/交易数/近期表现的多因子门控（`SmartWalletProfileStoreService.evaluateQualification:912-925`：winRate≥0.62、score≥0.70、trades≥25、PnL≥1000、回撤≤0.25；并有 7 天 observe 冷却）。但发现这些问题：
- **P1｜胜率分母含「平局(breakeven)」，把胜率算低**：`SmartWalletProfileTruthRefreshService` 的 `winRate = wins/total`，而 `total` 同时包含 `CLOSED_BREAKEVEN`（:241-244, :438-443），`wins` 只计 `pnl>0`。预测市场里临近 0.5 结算的平局很多 → 把好 leader 的胜率压到 0.62 阈值以下被误拒，同时拉低整体可见胜率。应改 `wins/(wins+losses)`。（注：`LeaderRollingPerformanceService:154` 又把 breakeven 当**亏损**，两处口径自相矛盾。）
- **P1｜手动 allowlist 绕过近期/冷却/leader 盈利门，只打日志不降权**：`SmartWalletSignalRiskService:159-164`（冷却绕过）、:660-677（leader 当前持仓不盈利只 WARN 不拒）。allowlist 在插入时快照质量、保留 30 天，期间 leader 转坏仍被跟。建议 allowlist 仍保留准入，但冷却期至少**降仓**、并在周度自动 allowlist 刷新里重算近期表现。
- **P1｜存在第二条弱门控的 LIVE 执行路径**：`SmartWalletFollowService.executeSignal`（controller `scan/executeSignal` 可达，`:107-115` 允许 LIVE）只做 `buildSignal` 的弱检查，**完全不走** `SmartWalletSignalRiskService` 的冷却/drift/leader 盈利门。若该端点被用于实盘，等于跳过了所有近期保护。建议下线或让它复用主门控。
- **P2｜leader 滚动门默认关**（`enableLeaderRollingGate=false`），其 ACTIVE/COOLING/SUSPENDED 状态机在生产不生效；建议评估开启。

### 3) 「是否对冲 / 对手盘」——⚠️ 无主动对冲（设计如此），但多结果市场有真实漏洞
- 系统**没有主动对冲**策略，只做「冲突规避 + 二元对手 BUY → 先平后可选反手」轮动。二元同市场 YES/NO 对立：默认阻止同时持有/同时挂单（`SmartWalletProperties:833-834`），对手 BUY 走 `DYNAMIC_FOLLOW_EXIT` 先平本方（`FollowPositionAdjustmentService:163-166`）——**这部分正确**。
- **P0｜negRisk 多结果市场完全不设防**：实体 `SmartWalletMarketInfoEntity` 只有 `marketId(conditionId)/outcome/tokenId/indexSet`，**没有 negRisk/事件分组字段**（已核实 :23-68），全包没有任何 negRisk 处理。Polymarket 多候选事件（如「谁赢大选」Trump/Biden/…）是**不同 conditionId**，只在事件层分组。跟两个 leader 进「Trump-YES」和「Biden-YES」是互斥赌注，但 marketId 不同 → **所有冲突门都不触发**，会同时持有互斥两边，至多一边能赢 → 扣费后必亏。建议给实体加 `negRiskMarketId/eventId` 分组键，冲突检测扩展到「同事件互斥结果」。
- **P1｜无锁竞态可同时开二元两边**：对立持仓/对立挂单检查都是无锁 `selectList`（`SmartWalletSignalRiskService:2660-2708`），乐观锁只防同一 task 重复（`claimTaskForExecution:523-547`），不串行化「同市场两个相反 task」。两个相反信号近乎同时到达可双双过门 → 双向暴露。建议按 `marketId/事件组` 加锁或唯一约束。

## 二、EV / 概率 / Kelly 仓位（核心定价逻辑，P0/P1）

- **P0｜Kelly 的「胜率」输入是被压缩的「跟单值得度」，EV 门退化成「价格<0.5」**：`KellyCalculator.java:96-103`：`p = 0.5 + (calibratedFollowProbability-0.5) * edgeFactor`。生产 `edgeFactor=0.15` 时，无论模型多自信，`p_win` 被压到约 **[0.46, 0.575]**。而 Kelly 分子 `p*odds-(1-p)>0` 恰好等价于 **`p_win > price`** → **价格>~0.575 的市场几乎一律被判负 EV 拒绝，价格<~0.46 的几乎一律通过**，与信号质量无关；通过后 Kelly 比例也极小且几乎不随信号强弱变化。更根本：`calibratedFollowProbability` 是「值得跟单的概率」，不是「该结果按价格 p 结算为真的概率」，二者被混用（代码注释也写着「Convert follow-worthiness score to event win probability」）。建议：`p_win` 用真实的市场公允概率/leader 隐含概率，而非把跟单分线性收缩到 0.5。
- **P1｜真正含手续费+滑点的净 EV 门在生产是关的**：`TradeProfitabilityScoringService:65-69` 正确算了 `净EV = p*毛边 - 手续费 - (期望+尖峰)滑点`，但唯一消费它的 G11 门要求 `enableProfitabilityGate`（默认 false，生产未开）+ 样本量。`enable-slippage-gate` 也=false。**结果：实际只有上面那个被压坏的 Kelly `p>price` 在当 EV 门，完全没扣手续费/滑点** → 真实净 EV 为负的单也会下。建议开启 `enable-profitability-gate=true`、`min-estimated-net-profitability-usdc>0`，并放宽样本量要求。
- **P1｜Kelly 之后没有重新套用「单笔≤1%资金」上限**：`maxSingleOrderCapitalRatio` 只钳了 Kelly 之前的 `preliminaryStake`（`SmartWalletSignalRiskService:771-781`），Kelly 用 `availableCapital` 重算并覆盖（:1042）后只剩 trigger-ratio 钳制，**单笔资金占比上限被绕过**。建议 Kelly 后重套该上限。
- **P2｜minOrder 地板把「该跳过的弱信号」抬成最小单下出去**：`KellyCalculator:124-125` 与 G10b 都把低于 minOrder 的仓位**上抬**到 minOrder，而不是跳过 → 最弱信号反而按最小单成交。

## 三、出场逻辑（止盈/止损/回收）

- **生产已开启**（DB `strategy_runtime_config` 实测）：`enable-auto-stop-loss=true`、`time-aware-stop-loss-enabled=true`、分层 `tiers=0.35/0.25/0.15/0.05`（按剩余小时收紧）、`enable-auto-take-profit=true(0.35)`、`capital-recycle.enabled=true`。方向/分层判断**正确**（`SmartWalletPositionSyncService.buildExitDecision:1085`）。所以「出场系统休眠」的担心在生产**不成立**（代码默认值 0.50 被 DB 覆盖为分层 0.35）。
- **P1｜allowlist 仓位被排除在所有自动出场之外**：`filterOutAllowlistPositions`（`SmartWalletPositionSyncService:249-294`、`CapitalRecycleExitService:86-124`）把手选「top leader」跟单仓**从止损/止盈/回收里全部剔除**。这些「你最信任」的仓位**没有任何止损**，一路扛到结算；若 leader 不卖或卖出事件漏抓，无保护。请确认是否有意，建议至少保留尾部止损。
- **P1｜资金回收死区偏正，砍掉「慢热的赢家」**：死区 `[-0.05, +0.08]`（`SmartWalletProperties:1162-1164`）+ 持仓 8h 即可被回收。一个 **+7% 且在涨**的长线赢家会被当「无效仓」按当前 bid 卖掉，放弃了奔向 1.0 的上行——而长线正是预测市场的主要 edge。建议把 `deadZoneHighRate` 收到 ~0.02，或对「正收益且趋势向上」豁免。
- **P1｜纸面平仓价失真**（与一节呼应）：止盈止损纸面按阈值价、跟随平仓纸面按 leader 价，均非本账户 bid → 纸面胜率/ROI 偏高。LIVE 路径会重解析 bid（`PolymarketClobExecutionService:405-450`，正确），但 PAPER 没有，而 PAPER 正是你的胜率度量面。
- **P2｜趋势止损要求严格单调下跌**（`TimeAwareStopLossService:130-134` 等）：薄盘口里相邻两次 bid 相等就重置，慢失血几乎不触发。建议改为「窗口内净下跌」。

## 四、修复优先级（按对盈利/胜率影响排序）

1. **P0 纸面成交按真实盘口**：开仓/平仓改用 `ShadowFillSimulationService` 或实时 bid；停止用 leader 价/阈值价记账。否则纸面胜率不可信，所有据此的决策都被带偏。
2. **P0 Kelly/EV 定价**：修正 `p_win` 语义（用公允概率）、重标 `edgeFactor`；并开启含手续费+滑点的净 EV 硬门，杜绝负 EV 下单。
3. **P0 negRisk 多结果对冲漏洞**：实体加事件分组键，冲突检测覆盖互斥结果，避免同时持有「必有一输」的多边。
4. **P1 leader 质量口径**：胜率分母剔除 breakeven；allowlist 不再绕过冷却/leader 盈利门（至少降仓）；下线/收口第二条弱 LIVE 路径。
5. **P1 出场**：allowlist 仓位至少保留尾部止损；回收死区上沿收紧别砍赢家；Kelly 后重套单笔资金上限。
6. **P2**：趋势止损放宽为净下跌；minOrder 地板改为「不足则跳过」；开启 leader 滚动门并评估。
