## 目标

部署不触发清仓。旧仓保持原退出语义、参数、保护状态、归属与成本；新仓使用新版本。持续监控、未决订单、扫描进度和单写锁有明确可验证的交接，接管失败不能制造新增风险或宣称健康。

## 成功标准

- [ ] 每个新仓提交订单前保存退出/指标参数、规则实现标识、账户/实例/策略/profile；退出使用该快照，修改新配置不影响旧仓。
- [ ] 存量未快照仓通过旧实例导出的可校验交接材料补齐，缺依据拒绝部署预检，不猜参数；现有止损不得因证据问题失效。
- [ ] LIVE按显式兼容归属恢复旧策略仓位及未决订单，保留原账本归属和预算释放键；账户与profile不可串用。
- [ ] PAPER兼容合约池与新入场风险配置变化，不重置初始权益/账本，移除合约仍管理旧仓；实例/账户/周期不隐式迁移。
- [ ] SIGTERM/SIGINT停止新增风险，当前步骤安全收口并落盘；重启先恢复/对账/接管验收，再开放新入场；异常杀进程仍可恢复同一意图。
- [ ] 持久化闭合bar进度、候选状态及市场上下文；恢复后按原期限和新行情重新检验，过期候选不补单；错误/恢复状态可观测。
- [ ] 双进程交接、未知提交结果、部分开平仓、同bar重启、损坏/缺失状态、账本失败、配置漂移和回滚均有验收证据。
- [ ] Python全套回归、真实只读API、隔离数据库/账本恢复演练、打包验证、迁移与回滚文档完成；生产操作另行批准。

## 范围与非范围

Python趋势运行时15m/4H及LIVE/PAPER/OBSERVE监控；复用现有权威MySQL与PAPER JSON，必要schema采用显式SQL迁移，启动不DDL。保持现有开平仓公式与正常周期。支持当前已知旧退出实现，未来不兼容实现必须提供保留适配器，预检不能用同名版本冒充兼容。
不接入事件交易，不改变账户准入，不撤用户手工订单，不合并/推送/部署或清理现网数据。不承诺重启间隔内零停顿，必须记录保护监控缺口与恢复状态。

## 状态转移与身份矩阵

运行实例：STARTING → RECOVERING → READY → DRAINING → STOPPED；任何状态失败 → DEGRADED/FAILED且不新开仓。持仓身份沿用account+原strategy+position_key，订单沿用client_order_id，恢复不新造身份。跨strategy的原instance_key须保留以释放原预算。

| 触发 | 期望结果 | 验证 |
|---|---|---|
| 同配置重启，有保护位/突破计数 | 原状态/规则继续，同bar不增计数 | LIVE/PAPER单测及进程演练 |
| 新退出参数/版本 | 旧仓不漂移，新仓采用新参数 | 双配置对照 |
| 未决/未知开单、部分成交 | 查询原单；不重复发单，不重复手续费 | 订单恢复矩阵 |
| 未决/部分平单 | 成交对账后更新剩余量，仅减仓 | 重启+累计成交矩阵 |
| 策略名称变化/移除合约 | 显式旧归属继续处理，保留账本 | 原归属/预算释放测试 |
| 参数/状态损坏、接管不全 | 禁止新增风险、明确缺项；不伪称就绪 | 故障注入 |
| SIGTERM / SIGKILL / 同时两个进程 | 排空或未完成标记；单写且可恢复 | subprocess+隔离账本/DB |
| 回退不兼容包 | 预检拒绝，保留可管理原仓的包 | 包/协议兼容测试 |

## 风险与缓解

旧配置不可从新env重建：导出旧进程白名单参数及实现hash，不输出凭据。仅保留version名称不足保证公式：实现hash校验+显式支持表。不兼容回滚漏管仓位：预检受支持policy/state协议。数据库/状态写失败：不新增风险，原持仓在可证明状态下管理，权威账本失败明确故障。PAPER状态目录更换可能形成空账本：交接身份/路径校验而非静默新建。

## 验证方式

本地pytest（全模块）及专项矩阵；两独立进程使用隔离状态与假交易所确定性成交服务；隔离MySQL验证事务、锁和预算；HTX只读公开API验证入口；release/package.py打包和verify。现网有仓热部署演练不在本轮未批准范围，需部署时单独验收。治理根check-docs-sync历史H-10单独记录，不伪造hash。
