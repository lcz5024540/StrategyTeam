## 5. 三组数据交叉解读（核心结论）

### 5.1 `smart_wallet_profile.win_rate` 存在系统性高估

`smart_wallet_profile.win_rate` 与 Polymarket Gamma `/leaderboard`、`/public-profile`、`/closed-positions` 同源，都只统计已 redeemed 的持仓。这相当于"幸存者偏差 + 用户行为偏差"两层失真：

- 用户**只 claim 赚钱的仓位**，亏损归零的仓不会被领回（因为收回 0 USDC，用户没有动机花 gas claim）。
- 因此 `closed-positions` 系统性偏向赢单。
- DB 里 11 个地址中：
  - **`0x9f2…2ca8`、`0x03e…1697` 画像 100% 胜率，真实 51%~53%** —— 47pt+ 失真。
  - **`0xa61…0abd` 画像 91.7%，真实 60.7%** —— 31pt 失真。
  - **`0xfbfd…0029` 画像 83.3%，真实 69.6%** —— 14pt 失真。

→ **`smart_wallet_profile` 不能直接当作下单依据**。本地 5/6 报告中 "profile 胜率 vs 内部跟单胜率严重背离" 的 root cause 即此处的链上事实。

### 5.2 真实 ROI 与画像 ROI 的差距更大

| 指标 | DB profile（API closed） | 真实（含未 claim 归零） |
|---|---:|---:|
| `0xfbfd…0029` ROI | 22.1% | **7.6%** |
| `0xdb27…c56e` ROI | 93.9% | **34.9%** |
| `0x03e…1697` ROI | 2.9% | **1.9%** |
| `0xa61…0abd` ROI | 1.9% | **1.9%** |

ROI 类似的下移说明：**胜率失真主要影响样本归类，但更大的真金白银亏损被隐藏在 redeemable 待领仓里**。`0xdb27…c56e` 单地址真实 ROI 仅 34.9%，看起来仍盈利，但其当前 21.5M USDC 的归零亏损总额相当于此前累计盈利的近一半。

## 7. 改进建议

按优先级排：

1. **立即修复 `smart_wallet_profile.win_rate` 取数**
   - 在拉 `/closed-positions` 之外，再拉 `/positions` 把 `redeemable=true & currentValue=0` 计入"亏损"。
   - 字段建议：增加 `unclaimed_loss_count`、`unclaimed_loss_cost`、`true_win_rate`（修正后）、`true_realized_pnl`。
   - 跟单门槛和 wallet_score 全部改用 `true_*` 系列。

2. **加一条"未 claim 归零比例" 拒入门槛**
   - 当 `unclaimed_loss_cost / (unclaimed_loss_cost + closed_realized_pnl) ≥ 30%` 时，地址转入 OBSERVE_ONLY；
   - 当 ≥ 60% 时，禁用真实跟单（PAPER 也降仓）。
   - 命中：`0xdb27…c56e`（21.5M / 67.65M ≈ 32%）、`0xfbfd…0029`（6.46M / 17.06M ≈ 38%）、`0x9495…9a27`（3.08M / 8.94M ≈ 34%）、`0x03e…1697`（0.56M / 2.25M ≈ 25%）。

3. **修复画像层的 wallet_score**
   - 基于 `true_win_rate` 而非 `win_rate`；
   - 引入"复制效率"反馈：内部 PaperROI - 外部 trueROI。该值持续 < 0 的地址降仓或暂停。

4. **核对 `0x9495…9a27` 是否要放大**
   - 我方 ROI +38.9% > 真实 ROI +18.2%，差距来自我方跟单只跟到了它最近表现极好的子集。
   - 但 99/100 当前持仓 redeemable，意味着该地址正在清旧批次，建议保持小额 paper canary、不放大。

5. **降低对 `0x2005…75ea` 的早期判定**
   - 真实 ROI +78%、胜率 96.8%，是 11 个地址里画像最强的。
   - 但本轮 33 笔我方跟单结果是 -21.6%。差距 100pt 不能用样本随机性解释，需要审 SKIP 规则、入场时机、市场子类是否过滤掉了它最赚钱的赛事市场。

## 9. 数据真实性复核（2026-05-07 补充，针对原报告第 2/4/5/6 节）

### 9.1 复核动机

UI 上 closed 订单页面**没有任何地址显示 100% 胜率**，但本报告第 2 节 `0x2005…75ea`、`0xe8dd…ec86` 等地址却给出 100%/95.1% 的"真实胜率"，与事实直接冲突。提出两个质疑：

- **Q1**：原结论是不是只基于 100~200 条样本？
- **Q2**：API 返回是不是按胜率/PnL 排序而非时间排序，导致前几页全是赢单？

### 9.2 复核脚本与原始数据

- 抓数：[`tmp_fetch_api.sh`](docs/polymarket/tmp_fetch_api.sh)（curl `/closed-positions`，PAGE=50，offset 范围 0~2999）。
