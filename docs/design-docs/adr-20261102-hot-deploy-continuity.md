# 热部署使用持仓参数快照与显式交接

2026-11-02；Codex；accepted（用户授权完善持仓延续）；类型2c。来源：support_htx_python@44d3150b与只读核验报告。

## 背景
旧仓已有状态恢复，但新环境参数可能影响原退出条件，策略名称变化可能漏管持仓与订单，进程停止没有明确排空协议。目标是部署不引入平仓或参数漂移。

## 备选
1. 保持现状：基础恢复存在，但不能证明完整接管，未选。
2. 部署前清仓、重新初始化：违背用户明确需求，未选。
3. 持仓快照+显式旧归属+运行检查点+接管验收：选择；保持原账本和单写锁，升级只作用于新入场。

## 决定
将完整ExitConfig、持仓信号参数、continuation版本、实例/账户/策略/profile和纯计算实现hash保存到现有每仓state JSON；新仓提交之前保存。PAPER使用其既有V4默认输入，不把LIVE环境参数强加给PAPER。旧未快照仓从旧包/进程参数白名单和身份清单导入，不复制瞬时保护计数、不猜历史配置。导入保留的是部署前实际有效规则，不声称重建所有历史开仓时环境。

显式兼容策略集合管理旧仓，费用与预算继续使用旧策略和稳定实例身份；不改名旧仓。持久运行检查点记录已处理bar、候选生命周期、市场上下文和健康摘要；恢复重新核验有效性。停止只请求排空，网络/SQL不进入信号处理器。下一进程必须拿锁、对账并验收所有受管仓位/订单才能READY。

接口默认拒绝未知协议或实现hash。若未来升级改动退出计算模块，必须保留旧实现适配或在停止旧进程前拒绝升级；不能修改version字符串冒充兼容。失败不新增风险，可确认的初始止损保持有效。

修改worker、LIVE/PAPER运行时、position manager、order accounting和存储接口。已读函数位置及模块依赖：[Python AST证据](../architecture-refactor/evidence/hot-deploy-20261102/python-call-surface.json)。本会话无可调用codegraph工具，采用AST和定点源码核验，不宣称执行codegraph。

## 后果
正面：旧仓行为可核对、配置调整与原仓隔离、接管失败可见。
负面：首次旧仓需要导出材料，不兼容代码不能直接回滚；检查点损坏必须恢复可靠副本而不能空启动。
中性：继续使用既有MySQL和PAPER JSON；部署短暂监控间隔必须记录，不以“热部署”承诺零停顿。

## 回滚
1. 预检目标包是否支持当前所有持仓policy/state协议和原strategy归属，任一失败禁止替换。
2. 停止新入场、排空并保留checkpoint及权威账本；不删除evidence/state。
3. 目标包拿锁后恢复验收，任何未决意图不明/仓位不一致/参数缺项则保持DEGRADED，不开新仓；由原兼容包继续管理或修复缺项。
