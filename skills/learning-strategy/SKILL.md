# 学习策略计划 (Strategy Learning & Planning)

本技能把「学习一个交易策略」变成「在 CoinStrategy 项目里能跑起来的实施计划」。分两阶段：**调研学习** → **落地规划**。

## 何时使用

- 用户想研究/学习一种交易策略（套利、网格、趋势、做市、跟单等）。
- 评估某策略是否值得在本项目实现。
- 把一个已理解的策略转成开发方案。

## 阶段一：策略调研学习

输出一份**策略学习笔记**，回答清楚以下问题：

### 1. 策略原理
- 核心逻辑是什么？靠什么赚钱（价差 / 资金费率 / 波动 / 信息差）？
- 一句话能不能讲清盈利来源？讲不清就是没真正理解。

### 2. 适用条件
- 适用什么市场/标的（CEX 永续、现货、Polymarket 预测市场…）？
- 需要什么市场环境（高波动 / 横盘 / 高资金费率）？
- 失效场景：什么情况下这套逻辑不成立甚至亏钱？

### 3. 关键参数
- 有哪些可调参数（阈值、仓位、周期、滑点容忍度）？
- 每个参数对收益/风险的影响方向。
- 推荐初始值与取值范围。

### 4. 风险点（金融项目必须写透）
- 市场风险：行情反向、流动性枯竭、滑点。
- 执行风险：下单延迟、部分成交、撤单失败、交易所宕机。
- 资金风险：保证金不足、爆仓、单边敞口。
- 用最坏情况估算最大可能亏损。

### 5. 收益预期与验证
- 理论收益率量级、收益频率。
- 如何回测 / 用历史数据验证。
- 成本：手续费、资金费率、Gas、滑点是否吃掉利润。

调研可借助 web 搜索、项目已有策略文档（`funding-rate/`、`polymarket/`、`*_STRATEGY.md`）作参考。

## 阶段二：落地到项目的实施计划

把策略映射到 CoinStrategy 的分层架构（参考 `coding-standards` 技能的分层表）：

### 1. 架构映射
- **策略逻辑**放 `coin-strategy-core`，只依赖 `common-api` 通用模型。
- **需要的交易所能力**：现有 `common-client`（Binance/OKX/Gate）是否够？缺的接口要补。
- **调度/运行**：放 `coin-strategy-job`，确定运行频率、触发方式。
- **配置与监控**：参数走配置，关键指标接入监控。
- 复用已有的跨策略基础设施（参考 `docs/polymarket/cross-strategy-reusable-infrastructure.md`）。

### 2. 任务拆解
- 用 superpowers 的 `writing-plans` 技能把方案拆成 2~5 分钟粒度的原子任务。
- 标出任务依赖与里程碑。
- 优先做「最小可验证版本」：先能跑通一笔，再加风控、再加优化。

### 3. 风控前置
- 实现策略**之前**先定义风控规则：最大仓位、单笔限额、止损、最大回撤、熔断条件。
- 风控代码和策略代码同等重要，不能事后补。

### 4. 验证计划
- 单元测试覆盖核心计算（用 `test-driven-development`）。
- 历史数据回测。
- 小资金灰度实盘（参考项目已有灰度 SOP）。
- 上线后监控指标与告警。

## 输出物

1. **策略学习笔记**：`docs/<策略名>/strategy-research.md` 或策略目录下。
2. **实施设计文档**：用 `doc-writing` 技能，按标准设计文档结构写，放 `docs/`。
3. **任务计划**：用 superpowers `writing-plans` 产出。

## 完成前自检清单

- [ ] 盈利来源是否一句话讲清楚了？
- [ ] 失效/亏钱场景是否写明？
- [ ] 最大可能亏损是否估算过？
- [ ] 是否映射到了正确的模块、遵守分层？
- [ ] 风控规则是否在实现前就定义好？
- [ ] 是否有回测 + 灰度的验证路径？
- [ ] 成本（手续费/资金费/Gas/滑点）是否纳入收益测算？

## 配套技能

- 调研结论落文档用 `doc-writing`。
- 拆任务用 superpowers 的 `writing-plans` 与 `brainstorming`。
- 实现阶段用 `coding-standards` + `test-driven-development` + `trading-security-audit`。
- 全过程进度用 `context-tracking` 记录。
