# 上下文记录 (Context Tracking)

本技能用于把「做了什么、没做什么、为什么、下一步」沉淀下来，让任何人（包括未来的自己和 AI）都能快速接续工作。

## 何时使用

- 一个跨多步骤的任务**开始时**：记录目标与计划。
- 任务**进行中遇到重要决策**时：记录决策与理由。
- 任务**结束或会话结束时**：记录完成项、未完成项、待办。
- 用户问「上次做到哪了」「这次改了什么」时。
- **主动**：每完成一块较大工作后，主动更新进度记录。

## 记录到哪里

- 项目级长期记忆：`.claude/projects/<project>/memory/MEMORY.md`（项目已有，作为索引/总览）。
- 单个功能/策略的进度：在该功能的 `docs/` 子目录或策略目录下建 `PROGRESS.md` 或带日期的进度文档（项目已有先例，如 `POLYMARKET_INTELLIGENCE_PROGRESS_SUMMARY.md`、`1小时观察报告-2026-05-19.md`）。
- 单次会话/排查：带日期的报告文件（`操作结果-YYYY-MM-DD.md`）。

原则：**短期、零散的记当前任务文档；跨任务、长期重要的记 MEMORY.md。**

## 记录模板

每次记录至少包含这四块：

```markdown
## 进度记录 — 2026-05-23

### 本次目标
（这次想达成什么）

### ✅ 已完成
- 做了 A，文件：path/to/file，效果：...
- 做了 B

### ⬜ 未完成 / 未做
- C 没做，原因：依赖未就绪 / 时间不够 / 需用户确认
- D 明确不在本次范围

### 🔑 关键决策
- 选择了方案 X 而非 Y，因为 ...（便于以后回溯，避免重复纠结）

### 📌 下一步 / 待办
- [ ] 待办 1（谁来做、依赖什么）
- [ ] 待办 2

### ⚠️ 风险 / 待确认
- 需要用户确认的问题
- 已知但未处理的隐患
```

## 「没做什么」为什么同样重要

很多返工源于不知道「某件事是故意没做」还是「忘了做」。所以必须显式记录：

- **故意不做**：写清楚原因（超出范围 / 风险太高 / 等依赖）。
- **想做但没做完**：写清楚卡在哪、下次从哪继续。
- **被否决的方案**：写清楚为什么否决，避免下次又走回头路。

## 好记录的标准

- **具体**：写清涉及的文件、模块、参数，不要只写「优化了代码」。
- **可追溯**：决策带理由，待办带负责人/依赖。
- **诚实**：没做完就写没做完，不夸大、不含糊。
- **及时**：趁记忆新鲜记录，不要拖到细节遗忘。
- **精简**：记要点，不抄全部代码；细节留在代码和正式文档里。

## 与项目记忆的关系

- 单次记录积累在任务文档里。
- 定期（如一个阶段结束）把重要结论、长期事实**上提**到 `MEMORY.md`，并精简过时内容。
- `MEMORY.md` 保持「索引 + 核心事实」的角色，不要变成流水账。

## 完成前自检清单

- [ ] 已完成项是否写清了文件/效果？
- [ ] 未完成项是否区分了「故意不做」和「没做完」并写了原因？
- [ ] 关键决策是否带理由？
- [ ] 待办是否可执行（有依赖/负责人）？
- [ ] 记录是否放在了合适的位置？
- [ ] 是否有需要上提到 MEMORY.md 的长期信息？
