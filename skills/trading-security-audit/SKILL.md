# 代码安全审查 (Trading Security Audit)

CoinStrategy 直接操作真实资金、API 密钥和链上私钥。**一个安全漏洞 = 真金白银的损失。** 本技能提供针对交易系统的安全审查清单。

## 何时使用

- 用户明确要求安全审查。
- 改动涉及：API key/secret、链上私钥、下单/撤单、转账、提币、签名、鉴权。
- 新增交易所对接、新增钱包操作。
- 上线前的安全检查（结合 superpowers `verification-before-completion`）。

## 审查范围与清单

### 1. API 密钥与 Secret
- [ ] apiKey / secretKey **绝不硬编码**在源码、配置示例、测试代码里。
- [ ] 密钥从安全来源加载（环境变量 / 加密配置 / 密钥管理服务）。
- [ ] 数据库中存储的用户密钥**加密存储**，不是明文。
- [ ] 密钥不出现在日志、异常堆栈、错误响应、前端。
- [ ] `.gitignore` 覆盖所有含密钥的文件；检查 git 历史是否曾误提交密钥。
- [ ] 交易所 API 权限最小化：只开「交易」，**不开「提币」**，绑定 IP 白名单。

### 2. 链上私钥（Polymarket / 链上策略）
- [ ] 私钥/助记词不硬编码、不进日志、不进前端、不进 git。
- [ ] 私钥在内存中的存活时间尽量短，用完不长期驻留。
- [ ] 签名操作有明确审计日志（签了什么、金额多少），但**不记私钥本身**。
- [ ] 参考项目已有的 `README-polymarket-private-key-workflow.md`，确认实现一致。

### 3. 资金安全
- [ ] 有**全局限额**：单笔最大下单额、单策略最大持仓、账户支配上限（README 提到只支配账户部分资金）。
- [ ] 下单前校验：余额充足、金额 > 0、不超限额、价格在合理区间。
- [ ] 滑点保护：限价单优先，市价单设最大可接受价。
- [ ] 异常行情熔断：价格异常波动时暂停下单。
- [ ] 提币/转账（若有）要有二次确认或白名单地址限制。

### 4. 下单与执行安全
- [ ] **幂等防重**：用客户端订单 ID，网络重试不会重复下单。
- [ ] 下单请求失败/超时后，**主动查询确认最终状态**，不假设成功或失败。
- [ ] 撤单失败有兜底处理，不留游离订单。
- [ ] 部分成交、拒单等边界情况都有处理分支。
- [ ] 交易所签名正确，时间戳/recvWindow 合理，防重放。

### 5. 日志与数据脱敏
- [ ] 日志、监控、告警、错误响应中无密钥、私钥、签名、完整 token。
- [ ] 必要时对地址、订单等做部分掩码。
- [ ] 异常堆栈不向前端/外部暴露内部细节。

### 6. 权限与接口安全（coin-strategy-web）
- [ ] 管理后台接口有鉴权，敏感操作（启停策略、改配置、改密钥）有权限校验。
- [ ] 用户只能访问自己的账户/策略数据，防越权（IDOR）。
- [ ] 输入校验：参数范围、类型、SQL 注入防护（用参数化查询）。
- [ ] 关键操作有审计日志（参考项目 `audit-observability` 文档）。

### 7. 依赖与配置
- [ ] 第三方依赖无已知高危漏洞（可跑依赖扫描）。
- [ ] 生产配置与测试配置分离，生产不开调试端点。
- [ ] 网络访问遵循 `docs/architecture-refactor/NETWORK_HARDENING.md`。

## 审查输出

产出一份审查报告，每个问题包含：

```
[严重程度] 问题标题
- 位置：文件:行
- 描述：是什么问题
- 风险：可能造成的后果（资金损失 / 密钥泄露 / 越权…）
- 建议：怎么修
```

严重程度分级：**严重**（可直接致资金损失/密钥泄露，必须立即修）/ **高** / **中** / **低**。

## 重要原则

- **只做发现和建议，不擅自改密钥配置或下单逻辑** —— 涉及资金的修改必须经用户确认。
- 发现疑似已泄露的密钥，立即提醒用户**轮换密钥**，不要只改代码。
- 拿不准是否安全时，按「不安全」处理并提请用户确认。

## 配套技能

- 上线前审查结合 superpowers 的 `verification-before-completion`。
- 写代码时同步遵守 `coding-standards`。
- 审查报告用 `doc-writing` 技能成文。
